1자연수의 합으로 3을 나타내는 순열

자연수의 합으로 n을 나타낼 수 있는 모든 순열의 개수를 구하시오.

노드의 수는 아직 만들어야 할 남은 값. 가지에 적힌 것은 이번에 더한 수. 0에 닿으면 한 가지가 완성된다.

3을 만드는 네 가지

  • 1 + 1 + 1
  • 1 + 2
  • 2 + 1
  • 3
순열이므로 1+2 와 2+1 은 다른 것으로 센다.
그래서 매번 1부터 다시 고른다. 조합이었다면 이렇게 하면 안 된다.

재귀로 옮기면

남은 값이 0 → 한 가지 완성, 1을 돌려준다.
아니면 1부터 남은 값까지 x를 골라, 남은 값 − x 를 다시 센다.

문제 1 · 3차시와 이어 보기

재귀는 곧 DFS다

스택을 직접 만들면 3차시 코드가 그대로 나온다.

숨어 있던 트리를 꺼내면

노드남은 합 (변수 node)
간선다음 항으로 x 를 고르는 것
node == 0 인 잎성공한 순열 하나

곧 이 문제는 트리의 잎을 세는 문제다.

3차시와 다른 점이 하나 있다.
3차시에는 트리가 tree 딕셔너리로 주어졌지만, 여기서는 트리가 코드 속에 숨어 있다. 상태 공간을 먼저 그려 내는 것이 진짜 실력이다.
방문 표시(visited)가 없다.
node 가 같아도 거쳐 온 경로가 다르면 다른 순열이기 때문이다. 3차시 트리 탐색과 같은 이유다. 
# DFS — 스택
def count_dfs(n):
    stack = [n]
    cnt = 0
    while stack:
        node = stack.pop()        # 맨 뒤 (LIFO)
        if node == 0:
            cnt = cnt + 1
            continue
        for x in range(1, node + 1):
            stack.append(node - x)
    return cnt
# BFS — 큐
def count_bfs(n):
    q = deque([n])
    cnt = 0
    while q:
        node = q.popleft()      # 맨 앞 (FIFO)
        if node == 0:
            cnt = cnt + 1
            continue
        for x in range(1, node + 1):
            q.append(node - x)
    return cnt
두 함수의 차이는 pop() 과 popleft() 딱 한 글자뿐이다. 그런데도 답을 찾아내는 순서는 완전히 달라진다. →
문제 1 · 3차시와 이어 보기

개수는 같고, 순서와 대가가 다르다

n = 4 일 때 찾아내는 순서

DFS 1+1+1+1 · 1+1+2 · 1+2+1 · 1+3 · 2+1+1 · 2+2 · 3+1 · 4
BFS 4 · 1+3 · 2+2 · 3+1 · 1+1+2 · 1+2+1 · 2+1+1 · 1+1+1+1
  • DFS는 사전순 — 한 갈래를 끝까지 파고들기 때문에 1+… 을 모두 끝낸 뒤에야 2+… 로 넘어간다
  • BFS는 항의 개수 순 — 레벨이 곧 지금까지 고른 항의 개수다
그래서 “가장 적은 항으로 n 을 만드는 방법”을 물으면 BFS는 처음 찾은 답이 곧 정답이다. 더 볼 필요가 없다.

그런데 BFS는 왜 위험한가

DFS는 지금 파고드는 한 갈래만 들고 있으면 되지만, BFS는 한 레벨을 통째로 큐에 쌓아 두어야 한다.

# DFS — 스택
def climb_dfs(n):
    stack = [0]
    cnt = 0
    while stack:
        c = stack.pop()          # 맨 뒤 (LIFO)
        if c == n:
            cnt = cnt + 1
            continue
        if c > n:                 # 지나쳤다
            continue
        for step in (1, 2):
            stack.append(c + step)
    return cnt

      
# BFS — 큐  (pop() 이 popleft() 로만 바뀐다)
def climb_bfs(n):
    q = deque([0])
    cnt = 0
    while q:
        c = q.popleft()          # 맨 앞 (FIFO)
        if c == n:
            cnt = cnt + 1
            continue
        if c > n:
            continue
        for step in (1, 2):
            q.append(c + step)
    return cnt

문제 4 · 한 걸음 더

  
나머지가 0이 될 때까지 — 유클리드 호제법

  
a를 b로 나눈 나머지를 r이라 하면 gcd(a, b) = gcd(b, r) 이다.
    이 성질을 한 번만 써서는 쓸모가 적다. 보통은 나머지가 0이 될 때까지 연속해서 쓴다.

  

    

      

        
연속해서 나누면

        

          
a= b·q1 + r1(0 < r1 < b)

          
b= r1·q2 + r2(0 < r2 < r1)

          
r1= r2·q3 + r3(0 < r3 < r2)

          
⋮

          
rn−2= rn−1·qn + rn(0 < rn < rn−1)

          
rn−1= rn·qn+1나머지 0

        

        
∴ gcd(a, b) = rn

      

      

        한 줄 내려갈 때마다 나누는 수가 다음 줄의 나눠지는 수가 되고, 나머지가 다음 줄의 나누는 수가 된다.

        나머지는 계속 작아지므로 언젠가 반드시 0이 된다. 그 직전의 나머지 rn이 최대공약수다.
      

    

    

      

        
예시 — gcd(1071, 1029)

        

          
1071= 1029 · 1 + 42

          
1029= 42 · 24 + 21

          
42= 21 · 2 + 0

        

        
∴ gcd(1071, 1029) = 21

      

      

        
코드로 보면 — 한 줄이 한 바퀴

        

          
바퀴aba % b

          
11071102942

          
210294221

          
342210

          
끝210b = 0 → 멈춤

        

        
a, b = b, a % b 가 “한 줄 내려가기”이고, while b != 0 이 “나머지가 0이 될 때까지”다.

count = 0


def f(start, sum, picked):
    global count

    if picked == 3:                  # ① 3개를 다 골랐다
        if sum % 3 == 0:
            count = count + 1
        return

    for i in range(start, N):        # ② 다음은 i 다음 수부터 고른다
        f(i + 1, sum + A[i], picked + 1)


f(0, 0, 0)
