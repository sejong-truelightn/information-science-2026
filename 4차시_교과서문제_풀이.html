개념이 노트북에서 걸리는 지점
return 과 print 의 차이 뼈대가 print('...', count(n)) 형태다. 함수는 값을 돌려줘야 한다. 함수 안에서 출력하면 None 이 같이 찍힌다

문제 1 · 교과서 175쪽

1자연수의 합으로 3을 나타내는 순열

자연수의 합으로 n을 나타낼 수 있는 모든 순열의 개수를 구하시오.

노드의 수는 아직 만들어야 할 남은 값. 가지에 적힌 것은 이번에 더한 수. 0에 닿으면 한 가지가 완성된다.

3을 만드는 네 가지

  • 1 + 1 + 1
  • 1 + 2
  • 2 + 1
  • 3
순열이므로 1+2 와 2+1 은 다른 것으로 센다.
그래서 매번 1부터 다시 고른다. 조합이었다면 이렇게 하면 안 된다.

재귀로 옮기면

남은 값이 0 → 한 가지 완성, 1을 돌려준다.
아니면 1부터 남은 값까지 x를 골라, 남은 값 − x 를 다시 센다.

문제 1 · 풀이

교과서 코드 — f(n)

먼저 스스로 생각해 본 뒤 눌러 보세요
def f(n):
    if n==0:
      return 1
    cnt = 0
    for i in range(n):
       cnt = cnt+f(i)
    return cnt

n = int(input())
print(f(n))
입력

실행 결과

f(i) 를 더하는 이유 — 마지막에 n−i 를 더해 n이 되었다면, 그 앞은 i를 만드는 모든 방법이다.
i는 0부터 n−1까지 가능하므로 f(0)+f(1)+…+f(n−1) 이 답이 된다.

문제 1 · 3차시와 이어 보기

그 재귀는 이미 DFS였다

함수 호출 스택이 눈에 보이지 않았을 뿐이다. 스택을 직접 만들면 3차시 코드가 그대로 나온다.

숨어 있던 트리를 꺼내면

노드남은 합 rest
간선다음 항으로 x 를 고르는 것
rest == 0 인 잎성공한 순열 하나

곧 이 문제는 트리의 잎을 세는 문제다. 재귀의 종료 조건이 “잎에 도착했다”는 뜻이었다.

3차시와 다른 점이 하나 있다.
3차시에는 트리가 tree 딕셔너리로 주어졌지만, 여기서는 트리가 코드 속에 숨어 있다. 상태 공간을 먼저 그려 내는 것이 진짜 실력이다.
방문 표시(visited)가 없다.
rest 가 같아도 거쳐 온 경로가 다르면 다른 순열이기 때문이다. 3차시 트리 탐색과 같은 이유다. 
# DFS — 스택
def count_dfs(n):
    stack = [n]
    cnt = 0
    while stack:
        rest = stack.pop()        # 맨 뒤 (LIFO)
        if rest == 0:
            cnt = cnt + 1
            continue
        for x in range(1, rest + 1):
            stack.append(rest - x)
    return cnt
# BFS — 큐
def count_bfs(n):
    q = deque([n])
    cnt = 0
    while q:
        rest = q.popleft()      # 맨 앞 (FIFO)
        if rest == 0:
            cnt = cnt + 1
            continue
        for x in range(1, rest + 1):
            q.append(rest - x)
    return cnt
두 함수의 차이는 pop() 과 popleft() 딱 한 글자뿐이다. 그런데도 답을 찾아내는 순서는 완전히 달라진다. →
문제 1 · 3차시와 이어 보기

개수는 같고, 순서와 대가가 다르다

n = 4 일 때 찾아내는 순서

DFS 1+1+1+1 · 1+1+2 · 1+2+1 · 1+3 · 2+1+1 · 2+2 · 3+1 · 4
BFS 4 · 1+3 · 2+2 · 3+1 · 1+1+2 · 1+2+1 · 2+1+1 · 1+1+1+1
  • DFS는 사전순 — 한 갈래를 끝까지 파고들기 때문에 1+… 을 모두 끝낸 뒤에야 2+… 로 넘어간다
  • BFS는 항의 개수 순 — 레벨이 곧 지금까지 고른 항의 개수다
그래서 “가장 적은 항으로 n 을 만드는 방법”을 물으면 BFS는 처음 찾은 답이 곧 정답이다. 더 볼 필요가 없다.

그런데 BFS는 왜 위험한가

DFS는 지금 파고드는 한 갈래만 들고 있으면 되지만, BFS는 한 레벨을 통째로 큐에 쌓아 두어야 한다.

문제 2 · 교과서 176쪽

2강인이의 계단 오르기

계단은 모두 n칸. 한 번에 1칸 또는 2칸을 오른다. 0번째 칸에서 n번째 칸까지 가는 서로 다른 방법의 수는?

노드는 지금 서 있는 칸 번호. 각 칸에서 +1 과 +2, 두 갈래로 갈라진다. n=4일 때 도착(초록)은 5가지.

상태를 무엇으로 잡는가

지금까지 어떻게 왔는지는 중요하지 않다.
지금 몇 번째 칸에 서 있는가만 알면 남은 방법의 수가 정해진다.

멈추는 조건이 두 개다

  • c == n → 정확히 도착. 성공 1가지
  • c > n → 지나쳤다. 0가지

두 번째를 빠뜨리면 계단을 넘어서도 계속 올라가 무한 재귀가 된다.

몇 번이나 나눠 보았을까

while d*d <= n:      # n ** 0.5 보다 안전
    if n % d == 0:
        return False
    d = d + 1

100 이하의 자연수 n과 k가 주어질 때, 1부터 n까지 중 k와 서로소인 수의 개수를 구하시오. (서로소 = 최대공약수가 1)

math.gcd 를 직접 만들면 — 유클리드 호제법

def gcd(a, b):
    while b != 0:
        a, b = b, a % b     # 반드시 동시에
    return a

a = b 를 먼저 쓰면 다음 줄의 a % b 가 바뀐 a를 써서 무한 반복에 빠진다.

53개를 골라 더하기

주어진 7개의 수 1 3 6 7 11 15 18 에서 3개를 선택하여 더할 때, 얻을 수 있는 수 중 3의 배수인 수의 개수는?

첫 수를 고르고, 그 다음 수부터 두 번째를 고르고, 또 그 다음부터 세 번째를 고른다. 이렇게 하면 겹치지 않게 35가지가 만들어진다.

경우의 수

순서를 고려하면 7 × 6 × 5 = 210가지
순서를 고려하지 않으면 7C3 = 35가지

고른 세 수를 더하기만 하므로 순서는 의미가 없다. 35가지만 보면 된다.

중복을 막는 장치

다음 호출에 i + 1 을 넘긴다.
i 를 그대로 넘기면 같은 수를 또 고르고,
0 부터 다시 돌리면 순서만 다른 중복까지 섞인다.

1+11+15 와 3+6+18 이 둘 다 27인 것처럼 다른 조합이 같은 합을 낸다.
문제 5 · 풀이

교과서 코드 — f(k, s, j)

먼저 스스로 생각해 본 뒤 눌러 보세요
A = [0, 1, 3, 6, 7, 11, 15, 18]
ans = 0

def f(k, s, j) :
  if j==3:
    if (s%3)==0:
      global ans
      ans = ans+1
    return

  for i in range(k+1, 8):
    f(i, s+A[i], j+1)
  return

f(0, 0, 0)
print(ans)
실행 결과
12
매개변수뜻
k다음에 고를 수의 시작 인덱스. 중복 선택을 막는다.
s지금까지 고른 수들의 합
j지금까지 고른 개수. 3이 되면 판정한다.
A 앞에 0을 넣은 이유 — 1번 인덱스부터 실제 데이터가 오게 하여 range(k+1, 8) 로 깔끔하게 돌기 위해서다.
0번부터 쓰고 싶다면 f(0, 0, 0) 대신 range(start, 7) 형태로 바꾸면 된다.

흔한 실수 두 가지

  • f(i, …) 로 넘긴다 → 같은 수를 여러 번 고른다
  • global ans 를 빠뜨린다 → UnboundLocalError
SUMMARY

다섯 문제, 하나의 순서

번호상태를 무엇으로 잡았나겹치지 않게 만드는 장치답
1아직 만들어야 할 남은 값순열이므로 매번 1부터 다시 고른다 (중복을 허용하는 것이 맞다)4
2지금 서 있는 칸 번호+1과 +2 두 갈래. c > n 이면 중단8
3판정할 수 하나2부터 시작해 1을 제외한다4
4판정할 수 하나gcd가 1인지만 본다7
5고른 세 수다음 호출에 i + 1 을 넘긴다12

문제를 만나면 이 순서로

  1. 상태를 정한다 — 무엇만 알면 나머지가 정해지는가
  2. 연결을 정한다 — 이 상태에서 갈 수 있는 다음은 어디인가
  3. 멈출 곳을 정한다 — 성공은 언제, 실패는 언제인가
  4. 겹치지 않게 만든다 — 같은 것을 두 번 세고 있지 않은가

완전 탐색을 먼저

느려도 좋다. 정확한 답의 기준이 되기 때문이다.
그다음 확인 횟수를 줄이고, 줄인 뒤에도 답이 같은지 처음 결과와 비교한다.

개선한 코드가 맞는지 확인할 방법이 없으면, 그것은 개선이 아니다.
