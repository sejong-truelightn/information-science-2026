00오늘 쓰는 트리

a ┌─────┴─────┐ b c ┌──┴──┐ ┌──┴──┐ d e f g │ ┌─┴─┐ │ h i j k
tree = { 'a': ['b', 'c'], 'b': ['d', 'e'], 'c': ['f', 'g'], 'd': ['h'], 'e': ['i', 'j'], 'f': ['k'], 'g': [], 'h': [], 'i': [], 'j': [], 'k': [] }
먼저 확인시킬 것 — 단말 노드도 반드시 [] 로 적어야 합니다. 빠뜨리면 tree['g'] 에서 KeyError 가 납니다. 학생들이 가장 먼저 만나는 오류입니다.

정답 순서는 이 두 줄입니다. 칠판에 미리 적어 두고 시작하면 학생이 스스로 채점할 수 있습니다.

DFS : a b d h e i j c f k g BFS : a b c d e f g h i j k

011번 · DFS 재귀 재귀

정답

visited = [] def dfs(node): # ① 현재 노드를 방문 기록에 추가 visited.append(node) # ② 자식을 순서대로 재귀 호출 → 더 깊이 내려간다 for child in tree[node]: dfs(child) # ③ for 문이 끝나면 = 더 갈 곳이 없음 → 백트랙 dfs('a') print(' -> '.join(visited))

설명할 때 짚을 것

  • ①이 for문 앞에 있는 이유. 방문 순서는 내려가는 순간 기록됩니다. for문 뒤로 옮기면 자식을 다 끝낸 뒤에 기록되어 순서가 h d i j e b k f g c a 로 완전히 뒤집힙니다. (이게 후위 순회입니다 — 여유가 있으면 실제로 옮겨서 보여주세요.)
  • 백트랙이 코드에 없다. ③에는 아무 코드도 없습니다. dfs(child) 가 끝나고 for문의 다음 반복으로 넘어가는 그 순간이 곧 백트랙입니다. 되돌아오는 일을 파이썬의 호출 스택이 대신해 줍니다.
학생이 자주 쓰는 틀린 코드
dfs(tree[node]) — 리스트를 통째로 넘깁니다. tree[['b','c']] 가 되어 TypeError.
def dfs(node): visited = [] — 함수 안에서 초기화하면 매번 비워져 결과가 [] 하나뿐입니다.
💬 "이 코드 어디에 '되돌아가라'는 명령이 있지?" → 없다. 그게 핵심. 💬 "①을 for문 뒤로 옮기면 출력이 어떻게 될까?" → 예측시킨 뒤 실행.

022번 · DFS 명시적 스택 반복문

정답

visited = [] stack = ['a'] # 루트를 넣고 시작 while stack: # ① top을 꺼낸다 (LIFO) node = stack.pop() # ② 방문 기록 visited.append(node) # ③ 자식을 역순으로 push for child in reversed(tree[node]): stack.append(child) print(visited)

이 표에서 반드시 짚어야 할 한 가지
3행에서 스택은 c e h 입니다. 그런데 그때 실제 경로는 a → b → d → h 죠. 둘이 다릅니다.
1번의 재귀에서는 호출 스택이 곧 "현재 경로"였지만, 여기 명시적 스택은 "앞으로 봐야 할 후보 목록"입니다. 같은 DFS라도 스택에 담긴 것의 의미가 다릅니다. 학생이 슬라이드의 "스택 = 현재 경로"와 헷갈리기 쉬운 지점입니다.
왜 reversed 인가
1행을 보세요. b, c 순으로 넣으면 스택은 b c 가 되고 top인 c가 먼저 나옵니다. c, b 순으로 넣어야 b가 먼저 나와 그림과 같은 순서가 됩니다.
reversed 를 빼면 이렇게 나옵니다.
a c g f k b e j i d h
틀린 답이 아니라 오른쪽 자식부터 내려간 DFS입니다. 이것도 정당한 DFS라는 점을 짚어 주면 좋습니다. "DFS의 방문 순서는 자식을 보는 순서가 정한다"가 결론입니다.
💬 "3행에서 스택이 c e h 인데, 지금 우리가 서 있는 경로는 뭐지?" → a-b-d-h. 다르다! 💬 "스택에 남아 있는 c와 e는 뭘 뜻할까?" → 아직 안 가 본 갈림길. 백트랙하면 돌아갈 곳.

033번 · BFS 큐 반복문

정답

from collections import deque visited = [] q = deque(['a']) # 큐에 루트 넣기 while q: # ① front를 꺼낸다 (FIFO) node = q.popleft() # ② 방문 기록 visited.append(node) # ③ 자식을 큐 뒤에 넣는다 for child in tree[node]: q.append(child) print(visited)
2번과 딱 두 글자가 다릅니다. stack.pop() → q.popleft(), 그리고 reversed 제거. 넣는 방식은 완전히 같습니다. 꺼내는 쪽만 바꿨는데 탐색 순서가 완전히 달라진다는 것이 오늘의 핵심입니다.

한 단계씩 추적 — 큐는 왼쪽이 front

큐 안을 들여다보면 — 4행의 큐 e f g h 에서 e·f·g는 레벨 2, h는 레벨 3입니다. 큐에는 언제나 인접한 두 레벨만 섞여 있습니다. 이것이 "한 겹씩 퍼진다"는 말의 정확한 뜻이고, BFS가 최소 이동 횟수를 보장하는 이유이기도 합니다.
popleft() 대신 pop() 을 쓰면
a c g f k b e j i d h
2번에서 reversed 를 뺐을 때와 완전히 같은 출력입니다. deque.pop() 은 뒤에서 꺼내므로 큐가 그대로 스택이 되어 DFS가 되어 버린 것이죠. 이 우연의 일치를 보여 주면 "자료 구조가 알고리즘을 정한다"는 말이 확 와닿습니다.
왜 deque 인가 — list.pop(0) 은 뒤의 원소를 전부 한 칸씩 당기므로 O(n)입니다. 이걸 큐로 쓰면 전체가 O(n²)이 됩니다. deque.popleft() 는 O(1).
💬 "4행 큐 e f g h 에서 h만 다른 게 뭐지?" → 레벨. 큐엔 두 레벨만 섞인다. 💬 "popleft 를 pop 으로 바꾸면 뭐가 될까?" → DFS. 실행해서 2번 결과와 대조.

044번 · BFS 레벨과 경로

정답

def bfs_path(root, goal): level = {} level[root] = 0 parent = {} parent[root] = None q = deque([root]) while q: node = q.popleft() for child in tree[node]: # ① 자식의 레벨은 부모보다 한 칸 깊다 level[child] = level[node] + 1 # ② 어디서 왔는지 기록 parent[child] = node q.append(child) # ③ 목표에서 거꾸로 되짚어 경로 복원 path = [] cur = goal while cur is not None: path.append(cur) cur = parent[cur] path.reverse() return level, level[goal], path
{'a': 0, 'b': 1, 'c': 1, 'd': 2, 'e': 2, 'f': 2, 'g': 2, 'h': 3, 'i': 3, 'j': 3, 'k': 3} a -> j : 레벨 3 , 경로 ['a', 'b', 'e', 'j']

설명할 때 짚을 것

  • 레벨은 "부모 + 1" 한 줄로 끝난다. BFS가 레벨 순서로 훑기 때문에, 자식을 처음 만나는 순간 그 값이 곧 최소 이동 횟수입니다. 따로 최솟값을 비교할 필요가 전혀 없습니다.
  • parent 는 화살표를 거꾸로 그려 둔 것. j에서 출발해 j → e → b → a 로 거슬러 올라가면 parent['a'] 가 None 이라 멈춥니다. 루트를 None 으로 둔 이유가 이 정지 신호입니다.
  • 이 패턴은 계속 재사용된다. 6번에서도, 심화 자료의 다익스트라·A*에서도 경로 복원은 똑같이 이 방식입니다.
path.reverse() 를 빼면
['j', 'e', 'b', 'a']
거꾸로 올라간 순서 그대로 나옵니다. 답이 틀린 게 아니라 방향만 뒤집힌 것이라는 걸 알려 주세요.
💬 "parent['a'] 를 None 말고 'a' 로 두면?" → 무한 루프. 정지 신호가 사라진다. 💬 "레벨 3인 노드가 h, i, j, k 네 개인데, 트리 그림의 어디지?" → 맨 아랫줄. 레벨 = 그림의 층.

055-1번 · 조합의 합 (재귀) 재귀

문제 — data = [3, 34, 4, 12, 5, 2] 에서 몇 개를 골라 합이 9 가 되는 조합을 모두 찾기.

정답

def dfs(i, total, picked): if total == target: found.append(list(picked)) return if total > target: # 가지치기 return if i == len(data): return # ① data[i] 를 고르는 경우 picked.append(data[i]) dfs(i + 1, total + data[i], picked) picked.pop() # ← 백트랙 # ② data[i] 를 고르지 않는 경우 dfs(i + 1, total, picked)
[3, 4, 2] [4, 5] 찾은 조합 수 : 2

설명할 때 짚을 것

  • 1번 DFS와 뼈대가 같습니다. 다른 점은 자식이 tree[node] 가 아니라 "고른다 / 안 고른다" 두 개로 코드 안에 직접 적혀 있다는 것뿐입니다. 트리가 메모리에 없어도 DFS는 성립합니다 — 이게 상태 공간 트리의 개념입니다.
  • picked.pop() 이 진짜 백트랙입니다. 1번에서는 파이썬이 알아서 해 줬지만, 여기서는 picked 리스트 하나를 계속 고쳐 쓰기 때문에 내가 직접 되돌려 놔야 합니다.
  • if total > target: return 은 4차시 예고편입니다. 더 봐도 소용없는 가지를 잘라내는 것 — 이것이 가지치기이고, 백트래킹·분기 한정법의 씨앗입니다.
실수 ① — list(picked) 를 빼고 found.append(picked) 라고 쓰면
[[], []]
조합 개수는 2개로 맞는데 내용이 비어 있습니다. 같은 리스트를 두 번 넣었고, 그 리스트가 나중에 비워졌기 때문입니다. "사본을 떠서 넣어야 한다"를 설명하기에 더없이 좋은 예입니다.
실수 ② — picked.pop() 을 빼면
[[3, 34, 4, 12, 5, 2], [3, 34, 4, 12, 5, 2, 12, 5, 2, 2, 34, 4, 12, 5]]
고른 것을 되돌려 놓지 않아 쓰레기가 쌓입니다. 백트랙이 없으면 어떻게 되는지를 눈으로 보여 줄 수 있습니다.
💬 "여기 트리가 어디 있지? tree 변수가 없는데?" → 트리는 재귀 호출 구조 자체다. 💬 "picked.pop() 을 지우면 뭐가 나올까?" → 예측시킨 뒤 실행. 반응이 좋습니다.

065-2번 · 조합의 합 (스택) 반복문

정답

found = [] stack = [(0, 0, [])] # (볼 차례, 지금까지의 합, 고른 수들) while stack: i, total, picked = stack.pop() if total == target: found.append(picked) continue if total > target: continue if i == len(data): continue # ① 고르지 않는 경우 (나중에 꺼내지도록 먼저 push) stack.append((i + 1, total, picked)) # ② 고르는 경우 (먼저 꺼내지도록 나중에 push) stack.append((i + 1, total + data[i], picked + [data[i]]))

여기엔 picked.pop() 이 없습니다. 상태마다 picked + [data[i]] 로 새 리스트를 만들어 넣기 때문에 되돌릴 것이 없습니다. 되돌아가는 일은 stack.pop() 이 대신합니다 — 10행에서 정답을 찾은 뒤 11행에서 스택에 남아 있던 (6, 7, [3, 4]) 를 꺼내는 것이 곧 백트랙입니다.

[[4, 5], [3, 4, 2]]
답은 같고 찾는 순서만 뒤집힙니다. 2번에서 reversed 를 뺐을 때와 정확히 같은 현상입니다.
💬 "3행에서 버린 가지에는 몇 개의 조합이 들어 있었을까?" → 34를 포함한 모든 조합. 한 번의 판단으로 통째로 삭제. 💬 "5-1과 5-2 중 어느 쪽이 이해하기 쉬웠나?" → 재귀/반복 선호를 확인하고 4차시 난이도 조절에 활용.

076번 · 최소 연산 횟수로 수 만들기

문제 — 1 에서 시작해 +1 또는 ×2 만으로 27 만들기.

정답

while q: now = q.popleft() if now == goal: break neighbors = [now + 1, now * 2] for nxt in neighbors: if nxt > goal: continue # ① 이미 만든 수라면 건너뛴다 if nxt in count: continue # ② 처음 만든 수다 → 횟수와 출처를 적고 큐에 넣는다 count[nxt] = count[now] + 1 parent[nxt] = now q.append(nxt)
최소 연산 횟수 = 7 만드는 순서 : [1, 2, 3, 6, 12, 13, 26, 27]

이 표가 BFS의 정의 그 자체입니다. "연산 1번으로 만들 수 있는 수를 전부 → 2번으로 만들 수 있는 수를 전부 → …" 그래서 27이 처음 등장한 줄의 번호가 곧 최소 횟수입니다. 더 짧은 방법이 있었다면 위쪽 줄에 이미 나왔을 테니까요. 4번의 level 표와 완전히 같은 원리입니다.
①이 왜 필요한가 — 1 + 1 = 2 와 1 × 2 = 2 가 둘 다 2입니다. 트리에서는 없던 일이죠. 서로 다른 길이 같은 수에 도달하므로, 확인하지 않으면 같은 수를 몇 번이고 큐에 넣게 됩니다. count 딕셔너리가 최소 횟수 기록과 방문 표시를 겸하고 있습니다.
if nxt > goal: continue 를 빼면 — 답은 7로 같습니다. 다만 27보다 큰 수(28, 32, 48…)까지 헛되이 만듭니다.
가지치기 O가지치기 X
큐에서 꺼낸 횟수2637
만들어 본 수의 개수2759
큐 최대 길이723
답은 같은데 일은 두 배 — 가지치기의 효과를 숫자로 보여 주기에 딱 좋은 비교입니다.
💬 "27을 만드는 데 왜 1→2→4→8→16→… 처럼 계속 ×2 하면 안 될까?" → 32로 넘어가 버린다. +1과 ×2를 섞어야 한다. 💬 "DFS로 풀면 어떻게 될까?" → +1 만 하며 1→2→3→…→27, 26번. 답은 찾지만 최소가 아니다.
