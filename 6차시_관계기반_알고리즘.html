Motivation

카드 100장을 다섯 명이 정리한다면교과서 202쪽 — 1~100이 적힌 카드를 순서대로 정리해야 한다.

① 나눈다

한 명이 20장씩 가져간다.
100장 정리 → 20장 정리 × 5

② 각자 푼다

20장 정리는 100장 정리와 같은 일이다.
크기만 작다.

③ 합친다

정리된 묶음 다섯 개를 모아 다시 순서대로 놓는다.

눈여겨볼 것은 ②다. 나눈 조각이 원래 문제와 모양이 같고 크기만 작다.
그래서 “20장 정리”를 풀 줄 알면 “100장 정리”를 풀 수 있다 — 작은 문제의 답과 큰 문제의 답 사이에 관계가 있기 때문이다.

큰 문제를 해결 가능한 작은 단위로 나눈 후, 작은 문제 간의 ‘관계’를 바탕으로 알고리즘을 설계하여 문제를 효과적으로 해결할 수 있다.

💬 말해 보자

큰 문제를 해결하기 위하여 작은 문제로 나누어 해결한 경험을 말해 보자.

예) 방 정리를 책상 · 침대 주변 · 옷장으로 나누어 한 곳씩 끝낸다. 시험 범위를 단원별로 나누어 공부한다.

Concept

관계기반 알고리즘의 설계문제를 분석하여 상태 공간을 정의하고, 각 상태를 함수로 나타낸 뒤, 이들 간의 관계를 점화식이나 유사한 형태로 표현하여 문제를 해결한다.

📐 설계의 두 조건

  1. 문제의 정의 및 상태를 함수 형태로 정의할 수 있어야 한다.
  2. 함수 간의 관계를 점화식 또는 이와 유사한 형태로 표현할 수 있어야 한다.
점화식 — 수열의 항을 앞의 항들로 나타낸 식.
aₙ = aₙ₋₁ + 3 처럼 “이번 값 = 앞의 값으로 만든 식”의 꼴이다.

수학적 귀납법 증명

명제 P(n)이 모든 자연수에서 성립함을 보인다.

  1. P(1)이 성립함을 보인다.
  2. P(k)가 성립한다고 가정하고, P(k+1)이 성립함을 보인다.

귀납적 설계 알고리즘

입력이 n인 문제의 해 f(n)을 구한다.

  1. 입력값이 n인 문제의 해를 f(n)으로 정의한다.
  2. f(1)의 값을 직접 구한다.
  3. 이미 계산한 값 f(k)를 통하여 f(n)의 값을 구한다.
귀납법을 증명의 도구가 아니라 설계의 도구로 쓴다.
“작은 답은 이미 안다고 치고, 그걸로 큰 답을 어떻게 만들지”만 생각하면 된다.

🔁 도미노로 보면

첫 번째 도미노를 넘어뜨릴 수 있고(f(1)), 어떤 도미노가 넘어지면 다음 도미노도 넘어진다면(f(k) → f(k+1)), 모든 도미노가 넘어진다. 컴퓨터는 이 도미노를 실제로 넘어뜨려 f(n)의 값을 얻는다.

⚠️ 둘 중 하나라도 빠지면

f(1)이 없으면 — 재귀가 끝없이 내려간다(RecursionError).
관계식이 틀리면 — 프로그램은 돌지만 틀린 답이 나온다. 작은 n으로 손 계산과 맞춰 보자.

Example · 교과서 203~204쪽

자연수 n이 주어질 때 1부터 n까지의 합f(n)을 1부터 n까지의 합으로 정의하면, f(n)을 f(n−1)을 이용하여 구할 수 있다.

f(n) = 1 + 2 + … + (n−1) + n
f(n) = f(n−1) + n
f(n) = 1n = 1f(n−1) + nn > 1
def f(k):
    if k == 1:          # f(1)은 직접 구한다
        return 1

    return f(k - 1) + k    # 이미 구한 f(k-1)로 f(k)를

n = int(input())
print(f(n))           # 입력 10 → 55

Concept · 교과서 205~206쪽

전체 문제와 부분 문제큰 문제를 여러 부분 문제로 나눈 후 부분 문제를 차례대로 해결해 나가면서 전체 문제를 해결할 수 있다.

전체 문제 서울에서 대전을 거쳐 부산으로 가는 가장 빠른 경로를 찾아라.
문제 해결 = (서울→대전 가장 빠른 경로) + (대전→부산 가장 빠른 경로)

🧩 관계기반 알고리즘의 부분 문제

항상 새로운 부분 문제를 만드는 것이 아니라, 같은 부분 문제가 여러 번 재사용되거나 재귀적 관계를 통하여 해결되는 문제를 말한다.

1부터 n까지의 합에서

f(n) = f(n−1) + n

k < n인 f(k)는 f(n)과 같은 함수 관계로 표현되지만, 크기가 작은 부분 문제이다.

더 알아보기 · 교과서 207쪽

subproblem과 partial problem우리말로는 둘 다 ‘부분 문제’지만, 쓰임새가 다르다.

subproblem

큰 문제를 여러 개의 작은 문제로 분해하는 방법을 나타낸다. 작은 문제들의 해결책이 합쳐져 전체 문제의 해결책이 된다.

  • f(n−1), f(n−2)로 f(n)을 만든다
  • 서울→대전 + 대전→부산
  • 20장 정리 × 5 → 100장 정리

분할 정복법, 동적 계획법, 재귀적 설계에서 자주 볼 수 있다. 이 단원의 ‘부분 문제’는 이것이다.

partial problem

원래 문제에 대한 완전한 해결책이 아닌 일부분만을 해결하는 문제를 나타낸다. 그 자체로는 전체 문제의 해결책이 되지 않는다.

  • 카드 100장 중 ‘짝수 카드만’ 정리하기
  • 큰 계획을 실행하는 도중에 생길 수 있는 문제를 미리 예측하여 해결하기
구별하는 질문 하나 — “이 답들을 모으면 전체의 답이 되는가?” 그렇다면 subproblem이다.
Divide and Conquer · 교과서 208쪽

분할 정복법전체 문제를 가장 간단하게 해결할 수 있는 수준까지 전체 문제와 같은 구조를 지닌 작은 문제로 분해한 후, 작은 문제를 차례대로 해결하는 과정을 통하여 전체 문제의 해를 구한다.

① 분할 (divide)

큰 문제를 동일한 구조의 작은 문제로 나눈다.

② 정복 (conquer)

충분히 작아진 문제의 해를 얻는다. 아직 크면 다시 분할한다 — 재귀.

③ 결합 (combine)

부분 문제의 해를 조합하여 큰 문제의 해를 만든다.

분할 정복법은 부분 문제의 정의와 그 사이의 재귀적 관계 설정이 중요하다. 분해 과정을 통하여 재귀 관계가 정의되고, 재귀 함수를 이용하여 알고리즘을 간결하게 구현할 수 있다. 앞에서 푼 1부터 n까지의 합도 이 모양이었다.
Merge Sort · 교과서 208~209쪽

8개의 수 8, 4, 1, 5, 7, 3, 2, 6을 오름차순으로 정렬해 보자자료를 반으로 나누고 각 부분을 정렬한 후 병합한다. 이 과정은 재귀적으로 반복된다.

합병 정렬의 네 단계

  1. 리스트의 길이가 1 이하이면 이미 정렬된 것으로 본다.
  2. 분할: 리스트를 절반으로 잘라 비슷한 크기의 두 부분 리스트로 나눈다.
  3. 정복: 각 부분 리스트를 합병 정렬을 이용해 정렬한다.
  4. 결합: 두 부분 리스트를 다시 하나의 정렬된 리스트로 합병한다.
Merge Sort · 교과서 210~211쪽

정렬된 두 리스트를 하나로 합치기두 리스트의 맨 앞끼리 비교해서 더 작은 쪽을 B에 옮긴다. 이것만 반복하면 된다.

A[low..mid]  ·  A[mid+1..high]  →  B

왼쪽 i
오른쪽 j
B
def f(low, high):
    if low >= high:              # 길이 1 이하 → 이미 정렬됨
        return
    mid = (low + high) // 2
    f(low, mid)                    # 분할 · 정복 (왼쪽)
    f(mid + 1, high)               # 분할 · 정복 (오른쪽)

    i = low                         # 결합
    j = mid + 1
    for k in range(low, high + 1):
        if j > high:                # 오른쪽을 다 썼다
            B[k] = A[i]; i = i + 1
        elif i > mid:               # 왼쪽을 다 썼다
            B[k] = A[j]; j = j + 1
        elif A[i] <= A[j]:
            B[k] = A[i]; i = i + 1
        else:
            B[k] = A[j]; j = j + 1
    for k in range(low, high + 1):
        A[k] = B[k]                 # B를 A로 복사

def f(low, high):
    if low >= high: return
    mid = (low + high) // 2
    f(low, mid)              # 왼쪽 절반 정렬
    f(mid + 1, high)         # 오른쪽 절반 정렬

def f(k):
    if k == 1:
        return 1
    if k == 2:
        return 2
    ans = f(k - 1) + f(k - 2)   # 분할 및 합병
    return ans                 # 입력 10 → 89

Dynamic Programming · 교과서 218~220쪽

  
동적 계획법복잡한 문제를 여러 부분 문제로 분해하여 해결하되, 부분 문제의 결과를 별도의 메모리 공간에 저장하고, 같은 부분 문제를 다시 만나면 저장해 둔 결과를 활용하여 계산의 중복을 피한다.

  

    

      

        

          
📋 동적 테이블

          
결과를 저장하는 리스트. 문제 해결 과정에서 끊임없이 갱신되므로 동적 테이블(Dynamic Table)이라고 부른다.

          

        

        

          
🔁 반복문을 활용한 동적 계획법

          
    
            
  • 점화식이 필요하다 — 분할 정복과 같은 점화식을 쓴다.
    • 
            
  • 가장 작은 부분 문제부터 차례대로 테이블을 채워 올라간다.
    • 
            
  • 재귀 함수를 부르지 않으므로 함수 호출 비용이 없다.
    • 
          

        

      

      

        
        

          
분할 정복 vs 동적 계획법

          
분할 정복은 f(n)에서 출발해 아래로 쪼개 내려가고, 동적 계획법은 f(1), f(2)에서 출발해 f(n)까지 위로 쌓아 올린다. 점화식은 같고 계산 순서만 뒤집었다.

        

        

          i번째 값을 한 번씩만 계산하므로 시간 복잡도가 O(2ⁿ)에서 O(n)으로 줄어든다.
        

      

    

  







  
동적 계획법을 활용한 문제 해결 (1) · 교과서 220~222쪽

  
2×n 격자판 채우기를 O(n)으로같은 점화식 f(n) = f(n−1) + f(n−2)를, 이번에는 값을 저장하면서 계산한다.

  

    

      

                
분할 정복 — 앞에서 쓴 격자판 코드


def f(k):
    if k == 1:
        return 1
    if k == 2:
        return 2
    return f(k - 1) + f(k - 2)

        
반복문을 활용한 동적 계획법


data = [0] * 1000000
n = int(input())
data[1] = 1
data[2] = 2
for i in range(3, n + 1):
    data[i] = data[i - 1] + data[i - 2]
print(data[n])                  # 입력 5 → 8

      

      

        

          
동적 테이블이 채워지는 순서

          

        

        

        

          
          
          
          
        

        

          점화식 f(k−1) + f(k−2)가 data[i−1] + data[i−2]로 그대로 옮겨졌다. 반복문 한 번에 칸 하나 — n칸이면 끝난다.
        

      

    

  







  
동적 계획법을 활용한 문제 해결 (2) · 교과서 223~225쪽

  
별 그리기에서 사용하는 ‘*’의 개수215쪽 별 그리기 패턴을 출력할 때 사용하는 ‘*’의 개수를 구해 보자. n = 1 → 1개, n = 2 → 4개, n = 3 → 11개

  

    

      

        
분할 정복


def f(k):
    if k == 1:
        return 1
    ans = 0
    ans = ans + f(k - 1)
    ans = ans + k
    ans = ans + f(k - 1)
    return ans

        
f(k−1)을 두 번 부른다. 호출이 2ⁿ−1번.

      

      

        
반복문 DP


data = [0] * 1000000
n = int(input())
data[1] = 1
for i in range(2, n + 1):
    data[i] = data[i-1] + i + data[i-1]
print(data[n])

        
f(n) = 1n = 1f(n−1) + n + f(n−1)n > 1

        
입력 10 → 실행 결과 2036 (두 코드 모두)

      

    

    

      출력해야 하는 별 그림은 2ⁿ−1줄이라 어떻게 해도 지수 시간이 든다. 하지만 별의 개수만 묻는다면 그림을 그리지 않고 관계만으로 O(n)에 구할 수 있다.

Q1. 관계기반 알고리즘 설계의 조건이 아닌 것은?

          

            
            
            
          

          
상태를 모두 방문하는 것은 탐색기반(전체 탐색)의 방식이다. 관계기반은 함수로 정의하고 점화식으로 관계를 세운다.

        

        

          
Q2. 1부터 n까지의 합 코드에서 if k == 1: return 1 을 지우면?

          

            
            
            
          

          
f(1)은 귀납적 설계의 첫 번째 도미노다. 이것이 없으면 재귀가 멈출 곳이 없어 RecursionError가 난다.

        

        

          
Q3. 계단을 한 번에 1칸, 2칸, 3칸 오를 수 있다면 n > 3에서 점화식은?

          

            
            
            
          

          
마지막 한 걸음이 1칸·2칸·3칸 세 경우로 나뉜다. 각각 n−1, n−2, n−3번째 칸에서 출발했다. 처음 세 값 f(1)=1, f(2)=2, f(3)=4는 직접 정한다.

        

      

      

        

          
Q4. 합병 정렬에서 ‘8 4 1 5’와 ‘7 3 2 6’을 각각 정렬한 다음 하는 일은?

          

            
            
            
          

          
‘1 4 5 8’과 ‘2 3 6 7’은 각각 정렬되어 있을 뿐, 이어 붙인다고 정렬되지 않는다. 앞에서부터 비교하며 합병해야 한다. 결합 단계에서 할 일이 없는 것은 퀵 정렬이다.

        

        

          
Q5. 반복문을 활용한 동적 계획법으로 2×n 격자판의 f(n)을 구할 때, 테이블을 채우는 순서는?

          

            
            
            
          

          
data[i]를 구하려면 data[i−1]과 data[i−2]가 이미 채워져 있어야 한다. 그래서 작은 부분 문제부터 차례대로 채운다. 각 칸을 한 번씩만 계산하므로 O(n)이다.

        

        

          
Q6. 다음 중 subproblem이 아닌 것은?

          

            
            
            
          

          
‘짝수 카드만’은 일부만 다루므로 그 결과를 아무리 모아도 100장 전체가 정리되지 않는다 — partial problem이다.

        

      

    

  







  
Wrap-up

  
오늘 배운 내용

  

    

      

        
📌 정리하기

        
    
          
  • 관계기반 알고리즘은 상태를 함수로 나타내고, 함수 간의 관계를 점화식이나 유사한 형태로 표현하여 문제를 해결한다.
    • 
          
  • 설계는 수학적 귀납법을 따른다 — 해를 f(n)으로 정의하고, f(1)을 직접 구하고, 이미 구한 f(k)로 f(n)을 구한다.
    • 
          
  • 문제를 부분 문제로 분해하면 복잡한 문제도 더 쉽게 해결할 수 있다.
    • 
          
  • 관계기반 알고리즘의 부분 문제는 원래 문제와 같은 함수 관계로 표현되지만 크기가 작은 문제이며, 여러 번 재사용된다.
    • 
          
  • 분할 정복법은 복잡한 문제를 간단하게 해결 가능한 작은 문제로 분해하고, 이를 차례로 해결하여 전체 문제의 답을 도출하는 알고리즘이다.
    • 
          
  • 동적 계획법은 부분 문제의 결과를 동적 테이블에 저장하여 계산의 중복을 피한다. 반복문을 활용한 동적 계획법은 가장 작은 부분 문제부터 차례대로 테이블을 채워 O(2ⁿ)을 O(n)으로 줄인다.
    •
