카드 100장을 다섯 명이 정리한다면교과서 202쪽 — 1~100이 적힌 카드를 순서대로 정리해야 한다.

① 나눈다

한 명이 20장씩 가져간다.
100장 정리 → 20장 정리 × 5

② 각자 푼다

20장 정리는 100장 정리와 같은 일이다.
크기만 작다.

③ 합친다

정리된 묶음 다섯 개를 모아 다시 순서대로 놓는다.

눈여겨볼 것은 ②다. 나눈 조각이 원래 문제와 모양이 같고 크기만 작다.
그래서 “20장 정리”를 풀 줄 알면 “100장 정리”를 풀 수 있다 — 작은 문제의 답과 큰 문제의 답 사이에 관계가 있기 때문이다.

큰 문제를 해결 가능한 작은 단위로 나눈 후, 작은 문제 간의 ‘관계’를 바탕으로 알고리즘을 설계하여 문제를 효과적으로 해결할 수 있다.

Concept

관계기반 알고리즘의 설계문제를 분석하여 상태 공간을 정의하고, 각 상태를 함수로 나타낸 뒤, 이들 간의 관계를 점화식이나 유사한 형태로 표현하여 문제를 해결한다.

📐 설계의 두 조건

  1. 문제의 정의 및 상태를 함수 형태로 정의할 수 있어야 한다.
  2. 함수 간의 관계를 점화식 또는 이와 유사한 형태로 표현할 수 있어야 한다.
점화식 — 수열의 항을 앞의 항들로 나타낸 식.
aₙ = aₙ₋₁ + 3 처럼 “이번 값 = 앞의 값으로 만든 식”의 꼴이다.

수학적 귀납법 증명

명제 P(n)이 모든 자연수에서 성립함을 보인다.

  1. P(1)이 성립함을 보인다.
  2. P(k)가 성립한다고 가정하고, P(k+1)이 성립함을 보인다.

귀납적 설계 알고리즘

입력이 n인 문제의 해 f(n)을 구한다.

  1. 입력값이 n인 문제의 해를 f(n)으로 정의한다.
  2. f(1)의 값을 직접 구한다.
  3. 이미 계산한 값 f(k)를 통하여 f(n)의 값을 구한다.
귀납법을 증명의 도구가 아니라 설계의 도구로 쓴다.
“작은 답은 이미 안다고 치고, 그걸로 큰 답을 어떻게 만들지”만 생각하면 된다.

🔁 도미노로 보면

첫 번째 도미노를 넘어뜨릴 수 있고(f(1)), 어떤 도미노가 넘어지면 다음 도미노도 넘어진다면(f(k) → f(k+1)), 모든 도미노가 넘어진다. 컴퓨터는 이 도미노를 실제로 넘어뜨려 f(n)의 값을 얻는다.

⚠️ 둘 중 하나라도 빠지면

f(1)이 없으면 — 재귀가 끝없이 내려간다(RecursionError).
관계식이 틀리면 — 프로그램은 돌지만 틀린 답이 나온다. 작은 n으로 손 계산과 맞춰 보자.

Example · 교과서 203~204쪽

자연수 n이 주어질 때 1부터 n까지의 합f(n)을 1부터 n까지의 합으로 정의하면, f(n)을 f(n−1)을 이용하여 구할 수 있다.

f(n) = 1 + 2 + … + (n−1) + n
f(n) = f(n−1) + n
f(n) = 1n = 1f(n−1) + nn > 1
def f(k):
    if k == 1:          # f(1)은 직접 구한다
        return 1

    return f(k - 1) + k    # 이미 구한 f(k-1)로 f(k)를

n = int(input())
print(f(n))           # 입력 10 → 55

호출 스택 — f(5)

Concept · 교과서 205~206쪽

전체 문제와 부분 문제큰 문제를 여러 부분 문제로 나눈 후 부분 문제를 차례대로 해결해 나가면서 전체 문제를 해결할 수 있다.

전체 문제 서울에서 대전을 거쳐 부산으로 가는 가장 빠른 경로를 찾아라.
문제 해결 = (서울→대전 가장 빠른 경로) + (대전→부산 가장 빠른 경로)

🧩 관계기반 알고리즘의 부분 문제

항상 새로운 부분 문제를 만드는 것이 아니라, 같은 부분 문제가 여러 번 재사용되거나 재귀적 관계를 통하여 해결되는 문제를 말한다.

1부터 n까지의 합에서

f(n) = f(n−1) + n

k < n인 f(k)는 f(n)과 같은 함수 관계로 표현되지만, 크기가 작은 부분 문제이다.

Divide and Conquer · 교과서 208쪽

분할 정복법전체 문제를 가장 간단하게 해결할 수 있는 수준까지 전체 문제와 같은 구조를 지닌 작은 문제로 분해한 후, 작은 문제를 차례대로 해결하는 과정을 통하여 전체 문제의 해를 구한다.

① 분할 (divide)

큰 문제를 동일한 구조의 작은 문제로 나눈다.

② 정복 (conquer)

충분히 작아진 문제의 해를 얻는다. 아직 크면 다시 분할한다 — 재귀.

③ 결합 (combine)

부분 문제의 해를 조합하여 큰 문제의 해를 만든다.

분할 정복법은 부분 문제의 정의와 그 사이의 재귀적 관계 설정이 중요하다. 분해 과정을 통하여 재귀 관계가 정의되고, 재귀 함수를 이용하여 알고리즘을 간결하게 구현할 수 있다. 앞에서 푼 1부터 n까지의 합도 이 모양이었다.
Merge Sort · 교과서 208~209쪽

8개의 수 8, 4, 1, 5, 7, 3, 2, 6을 오름차순으로 정렬해 보자자료를 반으로 나누고 각 부분을 정렬한 후 병합한다. 이 과정은 재귀적으로 반복된다.

합병 정렬의 네 단계

  1. 리스트의 길이가 1 이하이면 이미 정렬된 것으로 본다.
  2. 분할: 리스트를 절반으로 잘라 비슷한 크기의 두 부분 리스트로 나눈다.
  3. 정복: 각 부분 리스트를 합병 정렬을 이용해 정렬한다.
  4. 결합: 두 부분 리스트를 다시 하나의 정렬된 리스트로 합병한다.
Merge Sort · 교과서 210~211쪽

정렬된 두 리스트를 하나로 합치기두 리스트의 맨 앞끼리 비교해서 더 작은 쪽을 temp에 옮긴다. 이것만 반복하면 된다.

data[low..mid]  ·  data[mid+1..high]  →  temp

분할 정복법을 이용하여 정렬하기 — 퀵 정렬리스트를 피벗을 기준으로 두 개의 비균등한 크기로 분할한 후 부분 리스트를 정렬한다. 합병 정렬과 달리 결합 단계에서 할 일이 없다.

피벗으로 나누며 끝까지 정렬하기

i는 왼쪽에서 피벗보다 큰 값을, j는 오른쪽에서 피벗보다 작은 값을 찾는다. 둘을 교환하고, 엇갈리면 피벗과 j를 교환한다. 노란 테두리는 지금 피벗과 비교하는 값이다.

Quick Sort · 교과서 164쪽

퀵 정렬의 분할과 정복피벗을 제자리에 놓아 두 부분 문제로 나눈 뒤, 각각을 다시 퀵 정렬한다.

분할

  • left는 왼쪽에서 피벗보다 큰 값을, right는 오른쪽에서 피벗보다 작은 값을 찾는다.
  • 찾으면 break로 멈추고, 아니면 한 칸씩 옮긴다. 끝까지 못 찾으면 left는 end+1, right는 start에서 멈춘다.
  • 둘이 엇갈리지 않았으면 두 값을 교환하고 계속 찾는다.
  • 엇갈리면 피벗과 data[right]를 교환한다. 이제 피벗은 right 자리에 있고, 왼쪽은 모두 작고 오른쪽은 모두 크다.

정복 — 재귀 호출 두 줄

  • 피벗 왼쪽 start ~ right−1과 오른쪽 right+1 ~ end를 각각 퀵 정렬한다.
  • 피벗은 이미 제자리이므로 다시 볼 필요가 없다.
합병 정렬과 달리 결합 단계에서 할 일이 없다. 두 쪽이 정렬되면 피벗을 사이에 둔 채로 전체가 이미 정렬되어 있다.
합병 정렬 vs 퀵 정렬

재귀 호출은 어디에 두어야 할까?합병 정렬은 재귀 호출이 결합 앞에, 퀵 정렬은 재귀 호출이 분할 뒤에 있다.

합병 정렬 — 재귀 → 일

merge_sort(low, mid)       # → 왼쪽 절반은 정렬돼 있다
merge_sort(mid + 1, high)  # → 오른쪽 절반도 정렬돼 있다
정렬된 두 절반을 합병           # 위 두 줄 덕분에 가능

결합은 맨 앞끼리만 비교한다. 두 절반이 이미 정렬돼 있어야 맞는 방법이다.

재귀 호출 위치입력 5 3 1 4 2의 결과
for 문(결합) 앞[1, 2, 3, 4, 5] ✓
for 문(결합) 뒤[2, 4, 5, 1, 3] ✗

퀵 정렬 — 일 → 재귀

피벗을 기준으로 분할               # 피벗 자리 right가 정해진다
quick_sort(start, right - 1)  # right를 알아야 부를 수 있다
quick_sort(right + 1, end)

어디서 나눌지는 분할을 해 봐야 안다. 그래서 재귀 호출이 분할 뒤에 온다.

알고리즘먼저 필요한 것재귀 위치
합병 정렬합치려면 두 절반이 정렬돼 있어야일 앞
f(n) = f(n−1) + n더하려면 f(n−1) 값이 있어야일 앞
퀵 정렬나눠야 각 쪽을 정렬할 수 있어일 뒤
위치를 정하는 질문 하나 — “이 일을 하려면 재귀 호출의 결과가 필요한가?” 필요하면 재귀를 먼저, 재귀가 이 일의 결과를 필요로 하면 일을 먼저 한다.
재귀 호출 줄은 안으로 따라 들어가지 말고 ‘이 줄이 끝나면 이 구간은 정렬돼 있다’고 믿고 다음 줄을 읽는다. 이 믿음이 맞는 이유가 수학적 귀납법이다.

두 사람이 동시에 계단을 오른다엄지와 지수는 한 번에 1칸 또는 2칸을 오를 수 있다. 0번째 칸에서 출발하여 동시에 n번째 칸으로 오르는 서로 다른 방법의 수를 구해 보자.

  

    

      

        

        
칸을 누르면 그 값을 만드는 데 필요한 칸이 표시된다.

        

          
3. 0이 많은 이유

          
    
            
  • X[1][0] = 0 — 지수가 제자리에 있는데 엄지만 움직일 수는 없다. 동시에 움직이니까.
    • 
            
  • X[1][3] = 0 — 엄지는 1칸까지 1턴이면 끝나는데, 지수는 3칸까지 최소 2턴이 걸린다. 같은 턴 수에 도착할 수 없으니 0이다.
    • 
          

        

      

      

        

          
1. 상태와 규칙

          
한 사람이면 위치 하나(n)만 알면 되지만, 두 사람이니까 (엄지 위치 a, 지수 위치 b) 쌍이 상태다. 동시에 움직이니까 매 턴마다 두 사람 모두 1칸 또는 2칸을 올라간다. 한 명만 쉬는 건 안 된다. 그래서 한 턴에 생기는 경우는 2 × 2 = 4가지다.

          

            
엄지+1+1+2+2

            
지수+1+2+1+2

          

        

        

          
2. 점화식

          
(a, b)에 도착하기 직전에는 위 4곳 중 하나에 있었어야 한다.

          
X[a][b] = X[a−1][b−1] + X[a−1][b−2] + X[a−2][b−1] + X[a−2][b−2]
X[0][0] = 1  (둘 다 출발점에 서 있는 1가지)

          
표에서 빨간 칸 X[3][3]을 누르면 파란 칸 4개가 강조되는 게 바로 이 4곳이다.

          
X[3][3] = X[2][2] + X[2][1] + X[1][2] + X[1][1] = 2 + 1 + 1 + 1 = 5

          
같은 방식으로 X[5][5] = 11 + 5 + 5 + 5 = 26이다. 문제의 답은 대각선 X[n][n]이다.

        

      

    

    

      
코드는 이렇게 작성한다

      

        
① 표를 만든다. (n+1)×(n+1) 크기의 2차원 리스트 X를 0으로 채우고, X[0][0] = 1로 둔다.

        
② 작은 칸부터 채운다. a와 b를 0부터 n까지 이중 for 문으로 돈다. 필요한 칸은 a, b가 모두 더 작으므로 이미 채워져 있다.

        
③ 네 직전 칸을 더한다. 엄지가 오른 칸 1·2와 지수가 오른 칸 1·2를 돌며 X[a−엄지][b−지수]를 더한다. 인덱스가 0보다 작아지면 건너뛴다.

        
④ 대각선이 답이다. X[n][n]이 답이다.

오늘 배운 내용

  

    

      

        
📌 정리하기

        
    
          
  • 관계기반 알고리즘은 상태를 함수로 나타내고, 함수 간의 관계를 점화식이나 유사한 형태로 표현하여 문제를 해결한다.
    • 
          
  • 설계는 수학적 귀납법을 따른다 — 해를 f(n)으로 정의하고, f(1)을 직접 구하고, 이미 구한 f(k)로 f(n)을 구한다.
    • 
          
  • 문제를 부분 문제로 분해하면 복잡한 문제도 더 쉽게 해결할 수 있다.
    • 
          
  • 관계기반 알고리즘의 부분 문제는 원래 문제와 같은 함수 관계로 표현되지만 크기가 작은 문제이며, 여러 번 재사용된다.
    • 
          
  • 분할 정복법은 복잡한 문제를 간단하게 해결 가능한 작은 문제로 분해하고, 이를 차례로 해결하여 전체 문제의 답을 도출하는 알고리즘이다.
    • 
          
  • 동적 계획법은 부분 문제의 결과를 동적 테이블에 저장하여 계산의 중복을 피한다. 반복문을 활용한 동적 계획법은 가장 작은 부분 문제부터 차례대로 테이블을 채워 O(2ⁿ)을 O(n)으로 줄인다.
