03알고리즘이란 무엇인가

성능을 비교하기 전에, 먼저 "알고리즘"이 정확히 무엇인지 짚고 갑니다.
정의

Algorithm 이란 주어진 문제를 해결하기 위한 절차와 방법을 명확하고 체계적으로 정리한 것이다.

알고리즘이 갖추어야 할 5가지 조건
1
입력 Input

외부에서 제공되는 자료가 0개 이상 존재해야 한다.

2
출력 Output

적어도 하나 이상의 결과를 출력해야 한다.

3
명확성 Definiteness

각 단계는 모호하지 않고 명확하게 정의되어야 한다.

▶ 참고 영상 보기

4
유한성 Finiteness

유한한 횟수의 단계를 거친 후 반드시 종료되어야 한다.

5
효과성 Effectiveness

각 단계는 실제로 실행 가능한 연산이어야 한다.

Tip. 이 다섯 가지 조건 중 하나라도 만족하지 않으면, 아무리 유용해 보여도 "알고리즘"이라고 부르지 않습니다.

04알고리즘의 성능 평가란

문제를 해결하는 방법이 하나뿐이라면, 비교도 필요 없을 것입니다.

그러나 같은 문제를 해결하는 알고리즘은 하나가 아닙니다. 예를 들어 자료를 크기순으로 나열하는 "정렬" 문제 하나만 해도 버블 정렬, 삽입 정렬, 선택 정렬, 퀵 정렬 등 다양한 알고리즘이 존재합니다. (뒤에서 직접 비교해봅니다.)

그렇다면 여러 알고리즘 중에서 더 좋은 알고리즘을 어떻게 판단할 수 있을까요? 이를 위해 우리는 알고리즘의 성능(Performance)을 평가합니다.

시간 측면

문제를 해결하는 데 얼마나 걸리는가
→ 시간 복잡도(Time Complexity)

공간 측면

문제를 해결하는 데 메모리를 얼마나 쓰는가
→ 공간 복잡도(Space Complexity)

정리. 알고리즘 성능 평가는 결국 "시간"과 "공간", 이 두 가지 큰 축으로 이루어집니다.
알고리즘의 성능시간 복잡도

05평가 기준 ① 시간

알고리즘이 결과를 내기까지 걸리는 시간을 어떻게 표현할까요?
정의

알고리즘이 입력을 받아 결과를 출력하기까지 걸리는 시간을 의미한다.

실행 시간을 "초" 단위로 재면 안 되는 이유
  • 실행하는 컴퓨터의 사양(CPU 속도, 메모리 등)에 따라 달라진다.
  • 사용하는 프로그래밍 언어와 컴파일러에 따라 달라진다.
  • 실행하는 순간의 기기·서버 상태에 따라 달라진다.
그래서 실제 "시간(초)" 대신, 알고리즘이 수행하는 연산의 횟수로 성능을 표현합니다. 이를 입력 크기 n 의 함수로 나타낸 것이 시간 복잡도(Time Complexity)입니다.
알고리즘의 성능공간 복잡도

06평가 기준 ② 공간

알고리즘이 결과를 내기 위해 얼마나 많은 메모리가 필요할까요?
정의

알고리즘이 실행되는 동안 필요로 하는 메모리(저장 공간)의 양을 의미한다.

공간 복잡도에 포함되는 것
  • 입력 데이터를 저장하는 공간
  • 알고리즘 실행 중 사용하는 임시 변수, 배열 등의 공간
  • 함수 호출 시 쓰이는 추가 저장 공간(재귀 호출 등)
예시. 정렬할 데이터를 담을 새로운 배열을 추가로 만드는 알고리즘은, 원래 배열 안에서만 값을 바꾸는 알고리즘보다 더 많은 공간을 사용합니다.
알고리즘의 성능시간-공간 트레이드오프

07시간과 공간, 저울의 양 끝

둘 중 하나만 무조건 좋다고 말할 수 없는 이유가 있습니다.

많은 경우, 시간을 줄이려고 하면 공간을 더 많이 쓰게 되고, 반대로 공간을 아끼려고 하면 시간이 더 걸리는 경우가 많습니다. 이를 시간-공간 트레이드오프(Time-Space Trade-off)라고 합니다.

예시 · 메모이제이션(Memoization)

이미 계산한 값을 저장해 두었다가 다시 필요할 때 꺼내 쓰는 기법입니다. 시간은 절약되지만, 값을 저장해 둘 공간을 추가로 사용합니다.

결론. "무조건 좋은 알고리즘"은 없습니다. 문제 상황에 따라 시간과 공간 중 무엇을 더 중요하게 여길지 판단 기준을 정해야 합니다. (단, 다음 슬라이드 실습처럼 트레이드오프가 항상 나타나는 것은 아닙니다.)

(클릭하면 이미지가 나타납니다)

「강철의 연금술사」 — "뭔가를 얻으려면 그것과 동등한 대가가 필요하다는 뜻이지." 트레이드오프도 마찬가지입니다. 시간을 얻으려면 공간이라는 대가가, 공간을 아끼려면 시간이라는 대가가 필요합니다.

08[실습] 두 가지 방법, 무엇이 다를까

같은 결과를 내는 두 알고리즘의 시간·공간을 직접 비교해 봅니다.
문제

1부터 n까지의 자연수를 모두 더한 값을 구하시오. (예: n=5 → 1+2+3+4+5 = 15)

아래 방법 A와 방법 B는 같은 문제를 서로 다른 방식으로 푼 것입니다. 결과(정답)는 완전히 같지만, 그 과정에서 걸리는 시간이 다릅니다.

방법 A반복문으로 하나씩 더하기
total = 0 for i in 1..n: total = total + i

덧셈 연산을 n번 반복 수행 → 시간 O(n)

방법 B공식으로 한 번에 계산하기
total = n * (n + 1) / 2

곱셈·덧셈·나눗셈 약 3번 연산 → 시간 O(1)

n 값에 따른 연산 횟수 비교
↕ 아래로 스크롤해서 더 보기
입력 크기 n방법 A 연산 횟수방법 B 연산 횟수
n = 10약 10회약 3회
n = 100약 100회약 3회
n = 1,000약 1,000회약 3회
n = 10,000약 10,000회약 3회
n = 100,000약 100,000회약 3회
n = 1,000,000약 1,000,000회약 3회
공간 사용량은 어떨까? 두 방법 모두 정수형 변수(total, i 등) 몇 개만 사용하고, n이 커져도 추가로 쓰는 메모리가 늘지 않습니다. 즉 두 알고리즘 모두 공간복잡도는 O(1)로 동일합니다. 시간은 크게 차이 나지만(O(n) vs O(1)) 공간은 같다는 점에서, 트레이드오프가 항상 나타나는 것은 아니라는 사실을 확인할 수 있습니다.

09복잡도, 성능을 숫자로 표현하기

지금까지 "시간·공간이 중요하다"는 것을 배웠다면, 이제 이를 구체적으로 표현하는 방법을 배웁니다.
정의

복잡도(Complexity)란 알고리즘이 문제를 해결하는 데 필요한 자원(시간, 공간)의 양을 나타내는 척도이다.

  • 시간 복잡도: 문제 해결에 걸리는 시간을 정량적으로 나타낸 것
  • 공간 복잡도: 문제 해결에 필요한 메모리(기억장소)를 정량적으로 나타낸 것
복잡도 표현 방법
  • 복잡도는 일반적으로 연산 횟수를 이용해 표현한다.
  • 시간 복잡도는 알고리즘의 기본 연산(비교, 대입, 산술연산 등)이 실행되는 횟수로 계산한다.
  • 정확한 연산 횟수 자체보다, 입력 크기 n이 커질수록 연산 횟수가 어떻게 증가하는지 그 추세가 더 중요하다.
연결. 이 "증가하는 추세"를 간단한 기호로 표현하는 방법이 바로 다음에 배울 빅오 표기법입니다.

10빅오 표기법 (Big-O Notation)

알고리즘의 성능을 비교하는 공통 언어입니다.
정의

알고리즘의 실행 시간(연산 횟수)이 입력 크기 n에 따라 얼마나 빠르게 증가하는지를, 그 증가의 상한선을 기준으로 표현하는 방법이다. O(f(n)) 형태로 나타낸다.

표기법의 특징
1
최고차항만 남긴다

가장 영향력이 큰 항만 남기고 나머지는 생략한다. 예) n² + n + 5 → O(n²)

2
계수(상수)는 생략한다

예) 3n → O(n) / 100 → O(1)

3
n이 커질 때의 경향에 주목한다

입력이 아주 작을 때보다, 매우 커졌을 때의 증가율이 중요하다.

4
공통 비교 기준을 제공한다

서로 다른 알고리즘의 성능을 같은 잣대로 비교할 수 있게 해준다.

흔한 오해 바로잡기 · "코드가 길어지면 느려질까?"

많은 사람들이 "함수가 길어지면 성능이 나빠진다"고 생각해서 코드를 짧게 쪼개려고 합니다. 하지만 반복문이나 재귀가 없다면, 코드가 10줄이든 10,000줄이든 입력 크기 n과 무관하게 항상 정해진 만큼만 실행되므로 시간복잡도는 여전히 O(1)입니다.

핵심. 시간복잡도를 결정하는 것은 "코드의 줄 수"가 아니라 "입력 크기 n에 따라 반복되는 횟수"입니다. 즉 반복문·재귀의 유무와 그 반복 횟수가 핵심이며, 단순히 순차적으로 나열된 코드 줄 수는 시간복잡도에 영향을 주지 않습니다.

12코드로 보는 판단 기준

for문 개수로 판단할 수 있는 건 O(n), O(n²)뿐입니다. O(log n)은 "매번 절반씩 줄어드는가", O(2ⁿ)은 "재귀가 몇 갈래로 갈라지는가"로 판단합니다.
O(1)상수 시간

반복문 없이, 인덱스로 바로 접근

def get_first(arr): return arr[0]
O(log n)로그 시간

탐색 범위가 매번 절반으로 줄어듦

def binary_search(arr, target): low, high = 0, len(arr)-1 while low <= high: mid = (low + high) // 2 if arr[mid] == target: return mid elif arr[mid] < target: low = mid + 1 else: high = mid - 1 return -1
O(n)선형 시간

for문 한 겹, 전체를 한 번씩 방문

def sum_all(arr): total = 0 for x in arr: total += x return total
O(n log n)선형로그 시간

절반씩 나누기(log n) × 합치기(n)

def merge_sort(arr): if len(arr) <= 1: return arr mid = len(arr)//2 left = merge_sort(arr[:mid]) right = merge_sort(arr[mid:]) return merge(left, right)

13최선과 평균도 표현할 수 있을까?

빅오는 "최악의 경우"를 나타냅니다. 다른 상황을 나타내는 표기법도 있습니다.
Ω(g(n))오메가 표기법

알고리즘의 최소 시간 복잡도(최선의 경우)를 나타낸다.

정의: 어떤 양수 상수 c, n₀가 존재하여 모든 n≥n₀에 대해 f(n) ≥ c·g(n) 을 만족하면 f(n) = Ω(g(n))이다.

의미: f(n)은 적어도 g(n)만큼은 빠르게 증가한다 — "최소한 이 정도 시간은 걸린다"는 하한선을 보장한다.

Θ(g(n))세타 표기법

알고리즘의 정확한 시간 복잡도를 나타낸다. 최선과 최악이 같은 성능을 보일 때 사용된다.

정의: 어떤 양수 상수 c₁, c₂, n₀가 존재하여 모든 n≥n₀에 대해 c₁·g(n) ≤ f(n) ≤ c₂·g(n) 을 만족하면 f(n) = Θ(g(n))이다.

의미: f(n)은 g(n)에 비례하여 증가한다 — 상한과 하한이 같은 차수라는 뜻이다.

세 표기법 비교. 빅오(O)는 "최악에도 이 정도는 넘지 않는다"(상한), 오메가(Ω)는 "최선이어도 최소 이만큼은 걸린다"(하한), 세타(Θ)는 "항상 이 정도로 걸린다"(상한=하한)를 의미합니다.

20오늘의 배움 정리하기

Part 1과 Part 2에서 배운 내용을 하나로 연결해 봅니다.
Part 1 · 알고리즘의 성능
  1. 알고리즘은 입력, 출력, 명확성, 유한성, 효과성 다섯 조건을 만족해야 한다.
  2. 알고리즘 성능은 시간과 공간 두 측면에서 평가한다.
  3. 시간과 공간은 트레이드오프 관계일 수 있지만, 항상 그런 것은 아니다.
Part 2 · 알고리즘의 분석
  1. 복잡도는 성능을 정량적으로 나타내는 척도이며, 연산 횟수의 증가 추세로 표현한다.
  2. 빅오(O)는 최악의 경우(상한), 오메가(Ω)는 최선의 경우(하한), 세타(Θ)는 정확한 경우(상한=하한)를 나타낸다.
  3. 대표적 시간복잡도 순서: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
  4. 정렬 알고리즘마다 시간복잡도가 다르며, 상황에 맞는 알고리즘 선택이 중요하다.
