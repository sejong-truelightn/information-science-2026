복습과 연결

순서가 하나뿐인가, 여러 개인가

상태 공간을 어떤 구조로 만들었느냐에 따라, 쓸 수 있는 탐색 알고리즘이 달라진다.

선형 구조 비선형 구조
정의 상태 공간을 탐색하는 순서를 유일하게 결정할 수 있는 형태 한 원소를 탐색한 뒤, 연결된 여러 원소 중에서 다음을 선택해야 하는 형태
자료 구조 리스트, 큐, 스택 (2·3차원 배열도 순서를 정할 수 있으므로 선형) 트리, 그래프  오늘은 트리
탐색 알고리즘 순차 탐색 · 이분 탐색 깊이 우선 탐색(DFS) · 너비 우선 탐색(BFS)
다음 위치 언제나 1개 (i → i+1) 여러 개 → 선택과 되돌아오기(백트랙)가 필요

왜 갑자기 어려워지는가

선형 구조에서는 "다음"이 정해져 있으니 for i in range(n) 한 줄이면 끝났다. 비선형 구조에서는 갈림길마다 선택을 해야 하고, 막다른 길이면 돌아 나와서 다른 길을 시도해야 한다. 그래서 "어디까지 가봤는지"를 기억하는 보조 자료 구조(스택/큐)가 반드시 필요하다.

💡 우리 주변의 비선형 상태 공간

  • 폴더 구조 — 폴더 안에 폴더가 여러 개 (대표적인 트리)
  • 조직도 · 가계도 — 위에서 아래로 갈라진다
  • 가능한 경우의 수 — 동전 조합처럼 “다음에 무엇을 고를까”가 매번 갈라진다
  • 미로 — 갈림길에서 하나를 고르고, 막히면 되돌아옴
2차시와의 연결

다섯 요소는 그대로다 달라지는 것은 “상태 전이 규칙이 몇 개인가” 하나뿐이다

2차시에서 상태 공간을 초기 상태 · 목표 상태 · 상태 전이 · 경로 · 탐색 깊이 다섯 가지로 정의했다. 트리에서도 이 다섯은 그대로 쓰인다. 오른쪽 그림에서 각각이 무엇인지 확인하자.

상태 공간의 요소 2차시 — 선형 (순차 탐색) 오늘 — 비선형 (트리)
① 초기 상태
Initial State		 배열의 첫 인덱스 i = 0 루트 노드 a
탐색은 언제나 여기서 시작한다
② 목표 상태
Goal State		 arr[i] == 25 가 되는 인덱스 i=4 찾는 조건을 만족하는 노드 — 여기서는 j
③ 상태 전이
State Transition		 i → i+1
규칙이 하나뿐이라 다음 상태가 항상 하나로 정해진다		 부모 → 자식 (간선을 따라 한 칸)
자식이 여러 개여서 다음 상태를 골라야 한다
④ 경로
Path		 0→1→2→3→4
갈림길이 없어 경로가 단 하나		 a→b→e→j — 루트에서 내려온 길
갈림길이 있다 → 선택이 필요하고, 막히면 백트랙
⑤ 탐색 깊이
Search Depth		 목표까지의 전이 횟수 = 4
그대로 비교 횟수가 된다		 그 노드의 레벨 = 3
루트에서 몇 칸 내려왔는가가 곧 깊이다

🔀 바뀐 것은 ③ 한 줄뿐인데

전이 규칙이 1개 → 여러 개가 되었을 뿐이다. 그런데 그 결과로

  • 경로가 갈라지고 → 어느 쪽을 먼저 볼지 선택해야 하고
  • 막다른 길이 생기고 → 백트랙이 필요해지고
  • 어디까지 가봤는지 기억할 스택·큐가 필요해진다

상태 공간이 선에서 트리로 부풀어 오른다 — 오늘 배울 모든 어려움의 출처다.

이 트리에서 다섯 요소는
① 초기 상태 = a  ·  ② 목표 상태 = j  ·  ③ 상태 전이 = 부모→자식 한 칸
④ 경로 = a→b→e→j  ·  ⑤ 탐색 깊이 = 3

① 노드가 n개면 간선은 반드시 n − 1개다.

Depth-First Search

깊이 우선 탐색 일단 끝까지 내려가 본다, 막히면 돌아 나온다

🔍 정의

루트 노드에서 출발해 최대한 깊이 내려간 후, 더 이상 내려갈 수 없으면 다시 되돌아가며 다른 경로를 탐색하는 방법. 스택을 이용해 현재 방문 중인 경로를 저장하며 탐색한다.

백트랙(backtrack)
더 갈 곳이 없어 부모 노드로 되돌아가는 과정. 되돌아가야만 아직 가보지 않은 다른 갈래를 탐색할 수 있다.

👍 장점

  • 메모리 사용량이 적다 — 현재 경로만 저장
  • 트리의 깊이를 미리 알 수 없을 때 유용
  • 구현이 간단하다 (재귀 함수 3~4줄)

👎 단점

  • 최단 경로를 보장하지 못한다
  • 깊이가 깊으면 잘못된 가지를 오래 탐색
  • 재귀 깊이 제한에 걸릴 수 있다
시간 복잡도 O(n) (n = 노드 수 — 모든 노드를 한 번씩 방문)  ·  공간 복잡도 O(h) (h = 트리의 높이)
활용: 미로 찾기, 조합·순열 생성, 백트래킹 알고리즘의 뼈대 (→ 4차시)

🧠 한 문장으로

“갈림길에서 하나만 골라 끝까지 내려간다. 막다른 곳에서는 부모로 되돌아와 다음 갈래를 고른다.”

실제로는 구현이 간단한 깊이 우선 탐색을 더 많이 사용한다. 그 이유는 다음 두 차시에 드러난다 — 4차시의 백트래킹과 5차시의 분기 한정법이 모두 DFS 위에 세워지기 때문이다.

구현

DFS 코드 — 재귀와 스택, 두 얼굴

① 재귀 함수 (가장 많이 쓰는 형태)

함수 호출 스택이 곧 "현재 경로"다. 되돌아오는 동작(백트랙)이 함수가 끝나는 것만으로 자동 처리된다.

tree = {
  'a':['b','c'], 'b':['d','e'], 'c':['f','g'],
  'd':['h'],     'e':['i','j'], 'f':['k'],
  'g':[], 'h':[], 'i':[], 'j':[], 'k':[]
}
visited = []          # 방문 순서를 기록

def dfs(node):
    visited.append(node)           # ① 방문
    for child in tree[node]:    # ② 자식을 순서대로
        dfs(child)               #    더 깊이 내려간다
    # ③ for가 끝나면 = 갈 곳이 없음 → 백트랙

dfs('a')
print(' -> '.join(visited))
실행 결과  a -> b -> d -> h -> e -> i -> j -> c -> f -> k -> g
백트랙은 어디에 있는가?
코드에 백트랙을 위한 문장은 한 줄도 없다. dfs(child) 가 끝나고 for문의 다음 반복으로 넘어가는 순간이 곧 백트랙이다. 되돌아오는 일을 호출 스택이 대신해 준다.

② 명시적 스택 (반복문)

재귀 깊이 제한(파이썬 기본 1000)을 피하고 싶을 때 사용한다. 자식을 역순으로 push해야 재귀와 같은 순서가 나온다.

visited = []
stack = ['a']          # 루트를 넣고 시작

while stack:
    node = stack.pop()      # top을 꺼낸다 (LIFO)
    visited.append(node)
    # 역순 push → 왼쪽 자식이 먼저 pop된다
    for child in reversed(tree[node]):
        stack.append(child)

print(visited)
# ['a','b','d','h','e','i','j','c','f','k','g']
왜 reversed 인가?
스택은 나중에 넣은 것이 먼저 나온다(LIFO). b, c 순으로 넣으면 c가 먼저 꺼내진다. c, b 순으로 넣어야 b가 먼저 꺼내져 그림과 같은 순서가 된다.
“방문 표시”가 없는데 괜찮은가?
트리이기 때문에 괜찮다. 트리에는 사이클이 없고, 자식 쪽으로만 내려가므로 같은 노드를 두 번 만날 수 없다.
비선형 구조가 그래프가 되면 사정이 달라진다 — 사이클을 따라 영원히 돌 수 있어 visited 검사가 필수가 된다.
깊이 이해하기

백트랙은 어디에 있는가 재귀 함수가 되돌아오는 일을 대신해 주는 원리

DFS 코드에는 되돌아가라는 문장이 한 줄도 없다. 그런데도 백트랙은 정확히 일어난다. 그 일을 대신해 주는 것이 호출 스택이다.

1def dfs(node):
2 visited.append(node)
3 for child in tree[node]:
4 dfs(child)
5 # for문 끝 = 함수 끝 = return

전체 트리에서 b 아래쪽만 떼어 왔다. dfs('b') 를 한 걸음씩 실행해 본다.

호출 스택  ·  깊이 0

방문 순서

실행 중 스택에서 대기 중 반환 완료 아직 호출 안 됨

① 호출 = 나를 멈추고 맡긴다

dfs(b) 안에서 dfs(d)를 부르면, b의 실행은 그 줄에서 멈춘다. d가 자기 일을 완전히 끝내야 b가 다시 움직인다.

부른 쪽은 사라지지 않는다. 기다릴 뿐이다.

② 호출 스택 = 멈춘 나들의 더미

파이썬은 멈춰 있는 함수들을 부른 순서대로 쌓아 둔다. 맨 위 하나만 실제로 실행 중이고, 그 아래는 전부 자식을 기다리는 중이다.

쌓인 것을 아래→위로 읽으면 그게 루트에서 현재까지의 경로다.

③ 반환 = 더미가 하나 줄어든다

함수가 마지막 줄을 지나면 그 층이 스택에서 사라지고, 바로 아래 층이 멈췄던 자리에서 다시 이어진다.

이 자동 복귀가 곧 백트랙이다.

정리하면 — 방향이 반대다. dfs(child) 는 내려가는 동작(호출)이고, 백트랙은 그 호출이 끝나서 돌아오는 동작(반환)이다. 그래서 코드에는 내려가는 줄만 보이고, 올라오는 줄은 보이지 않는다.
코드에서 일어나는 일실제로 일어나는 일
dfs(child) 줄을 만난다내려간다 — 스택에 층이 하나 쌓인다
그 호출이 끝난다백트랙 — 층이 사라지고 부모로 자동 복귀
for문의 다음 반복부모가 다음 갈래를 고른다
5번 줄에 도달더 갈 곳 없음 → 내가 반환될 차례
❓ 그런데 왜 h까지 내려갔다가 e로 갈 수 있지?
b의 for문이 d에서 멈춘 채 스택에 남아 있기 때문이다. d가 반환되면 b는 멈췄던 그 자리에서 다음 반복(e)으로 이어간다. 기억해 두는 일은 아무도 시키지 않았다 — 스택이 하고 있었다.

스택 — 맨 뒤에서 꺼낸다 (LIFO)

방문 순서

방금 꺼낸 노드 스택에서 대기 중 처리 완료 아직 발견 안 됨
🔎 백트랙을 눈으로 찾는 법
pop 한 노드가 방금 처리한 노드의 자식이면 → 한 칸 내려간 것이다.
자식이 아니면 → 그 사이에 백트랙이 일어난 것이다. 재귀에서 함수가 반환되던 자리가 바로 여기다.
재귀 (10페이지)명시적 스택 (지금)
스택의 정체파이썬의 호출 스택내가 만든 리스트
쌓이는 것함수 층 (실행 위치까지 기억)노드 이름만
백트랙함수가 반환 — 코드에 안 보임pop — 코드에 보임
깊이 제한있음 (기본 1000)없음
방문 순서b → d → h → e → i → j — 완전히 같다
❓ 왜 reversed 가 필요한가?
d, e 순으로 push하면 스택 맨 뒤는 e가 되어 e가 먼저 꺼내진다. 왼쪽 자식부터 가려면 e, d 순으로 넣어야 한다. 재귀는 for문이 순서대로 도니까 이 뒤집기가 필요 없었다.
Breadth-First Search

너비 우선 탐색 가까운 곳부터 차례차례, 물결이 퍼지듯

🔍 정의

루트 노드에서 인접한 노드(자식)들을 모두 탐색한 후, 그다음 깊이로 넘어가는 방식. 깊이가 얕은 순서대로 탐색하므로 최단 경로를 찾는 데 적합하다. 큐를 이용하여 각 레벨에 해당하는 노드를 저장하면서 탐색을 진행한다.

왜 최단 경로가 보장되는가?
레벨 1을 전부 본 뒤에야 레벨 2로 넘어간다. 그러므로 어떤 노드를 처음 만나는 순간이 곧 루트로부터의 최소 이동 횟수(= 그 노드의 레벨)다. 단, 모든 간선의 비용이 같을 때만!

👍 장점

  • 최소 이동 횟수를 보장한다
  • 방문 순서가 예측 가능하다 (레벨 순)
  • 레벨(깊이) 정보를 자연스럽게 얻는다

👎 단점

  • DFS보다 메모리를 많이 쓴다 — 한 레벨 전체를 큐에 담음
  • 자식이 많은 트리에서는 큐가 급격히 커진다
  • 구현이 DFS보다 조금 길다
시간 복잡도 O(n) — DFS와 같다. 차이는 방문 순서이지 총 작업량이 아니다.
공간 복잡도는 한 레벨의 최대 노드 수에 비례한다 → 넓은 트리일수록 불리
활용: 미로 최단 경로, 네트워크 최소 홉 수, 촌수 계산, 레벨별 처리

“물에 돌을 던지듯, 가까운 원부터 한 겹씩 넓혀 나간다.”

큐에 들어 있는 노드들은 거의 같은 레벨이다. 이것이 “한 겹씩 퍼진다”의 정체다.

구현

BFS 코드 — 큐 하나로 끝난다

from collections import deque

def bfs(root):
    visited = []
    q = deque([root])          # 큐에 루트 넣기

    while q:
        node = q.popleft()     # ① front를 꺼낸다 (FIFO)
        visited.append(node)   # ② 방문 기록
        for child in tree[node]:
            q.append(child)    # ③ 큐 뒤에 넣는다
    return visited

print(bfs('a'))
# ['a','b','c','d','e','f','g','h','i','j','k']
DFS 스택 코드와 딱 두 군데가 다르다
① stack.pop() → q.popleft()  (맨 뒤 → 맨 앞)
② reversed(...) 를 뺀다
나머지는 줄 순서까지 그대로다. 꺼내서 기록하고, 자식을 넣는다. 꺼내는 쪽만 바꿨는데 탐색 순서가 완전히 달라진다.
흔한 실수: list.pop(0) 은 뒤의 원소를 전부 한 칸씩 당기므로 O(n)이다. 이걸 큐로 쓰면 전체가 O(n²)이 된다. 반드시 deque 의 popleft() 를 쓰자. (O(1))
방문 기록을 언제 하는가
visited.append(node) 가 꺼내는 줄 바로 아래에 있다. 넣을 때가 아니라 꺼낼 때 기록한다 — DFS 스택 코드와 같은 자리다.
BFS는 FIFO라서 넣은 순서 = 꺼낸 순서다. 그래서 넣을 때 기록해도 결과는 같다. 다만 트리에서만 그렇다. 이 차이는 다음 장에서 다시 다룬다.

큐 — 맨 앞에서 꺼낸다 (FIFO)

방문 순서

방금 꺼낸 노드 큐에서 대기 중 처리 완료 아직 발견 안 됨
DFS와 다른 곳은 4번 줄 하나뿐이다
stack.pop() — 맨 뒤에서 꺼낸다 → 방금 넣은 것부터 → 깊이
q.popleft() — 맨 앞에서 꺼낸다 → 먼저 넣은 것부터 → 너비
넣는 코드는 완전히 같다. 꺼내는 쪽만 바꿨을 뿐이다.
같은 트리, 다른 순서방문 순서왜
DFS (스택)b → d → h → e → i → jd로 내려가면 h까지 끝까지 간 뒤에야 e를 본다
BFS (큐)b → d → e → h → i → jd, e를 먼저 다 본 뒤에야 아래층으로 내려간다
👀 큐의 모양을 눈여겨보자
큐 안에 들어 있는 노드들은 항상 같은 층이거나 이웃한 두 층뿐이다. 층이 순서대로 채워지므로, 목표를 처음 만나는 순간이 곧 최소 이동 횟수가 된다.
❗ 방문 기록은 꺼낼 때, 다만 트리에서만
여기서는 꺼낼 때(4번 줄) 기록한다. BFS는 FIFO라 넣은 순서 = 꺼낸 순서이므로, 넣을 때 기록해도 결과는 똑같다. 코드가 DFS 스택 버전과 나란히 서는 쪽을 택했을 뿐이다.
그래프라면 이야기가 달라진다. 두 갈래가 같은 노드로 모일 수 있어서, 넣을 때 표시하지 않으면 같은 노드가 큐에 여러 번 들어간다.
헷갈리기 쉬운 지점

방문 기록을 ‘언제’ 하는가 — 서로 다른 두 이야기 비슷하게 들리지만 완전히 다른 두 축이다. 섞이면 반드시 헷갈린다.

축 1  선방문 · 후방문 (전위 · 후위 순회)

DFS 재귀에서만 나오는 이야기다.
기록을 dfs(child) 앞에 두느냐 뒤에 두느냐. 

def dfs(n):
    visited.append(n)   # ← 앞
    for c in tree[n]:
        dfs(c)
def dfs(n):
    for c in tree[n]:
        dfs(c)
    visited.append(n)   # ← 뒤
전위(선방문)a b d h e i j c f k g
후위(후방문)h d i j e b k f g c a
결과가 완전히 달라진다. 순회의 종류 자체가 바뀌는 것이므로, 문제가 요구하는 쪽을 골라야 한다.

👀 왜 무너지는가 — reversed 가 범인이다
스택은 맨 왼쪽 자식을 마지막에 넣어야 먼저 꺼내진다. 그래서 reversed 로 뒤집어 넣는다.
그런데 넣는 자리에서 기록하면 그 뒤집힌 순서 그대로 기록되어 e가 d보다 먼저 적힌다. 게다가 기록만 앞서고 실제 방문은 한참 뒤에 일어나므로, 만들어진 목록은 깊이 우선도 너비 우선도 아니다.
실험해 볼 것 — 넣을 때 기록 모드에서 파란 순번 배지가 붙는 순간을 보자. e와 d에 배지가 먼저 붙고(2·3번), 정작 빨간색으로 꺼내지는 것은 한참 뒤다. 기록과 방문이 어긋나 있다는 것이 눈에 보인다. → 스택 DFS는 반드시 꺼낼 때 기록한다.

스택에서는 결과가 무너졌다. 큐에서도 그럴까? 먼저 예상해 보고 버튼을 눌러 확인하자.

1q = deque([root]); visited = []
2while q:
3 node = q.popleft()
4 visited.append(node) # ← 꺼낼 때
5 for child in tree[node]:
6 q.append(child)
1q = deque([root]); visited = [root]

3 node = q.popleft()
4 for child in tree[node]:

스택 버전과 줄 위치까지 똑같다. 다른 곳은 popleft() 와 reversed 가 없다는 것뿐.

큐 — 맨 앞에서 꺼낸다 (FIFO)

방문 순서

방금 꺼낸 노드 큐에서 대기 중 처리 완료 기록된 순번
기록 시점이 트리(b 아래)의 방문 순서BFS인가
꺼낼 때b → d → e → h → i → j✓
넣을 때b → d → e → h → i → j✓
👀 결과가 똑같다 — 뒤집기가 없기 때문이다
큐는 FIFO라 넣은 순서 = 꺼낸 순서다. 어느 쪽에서 목록을 만들어도 같은 수열이 나온다.
차이는 시점뿐이다 — 넣을 때 기록하면 배지가 조금 일찍 붙지만, 붙는 차례는 바뀌지 않는다.
❗ 단, 그래프에서는 넣을 때 표시하는 쪽이 오히려 옳다
그래프는 두 갈래가 같은 노드로 모일 수 있다. 꺼낼 때만 표시하면 그 노드가 큐에 여러 번 들어가 중복 처리된다. 큐에 넣는 순간 표시하면 한 번만 들어간다. 트리에서는 아무 차이가 없지만, 그래프로 넘어가면 이 선택이 중요해진다.
🧾 세 실험을 한 줄로
재귀(전위 · 후위) → 순서가 완전히 달라진다 · 스택(LIFO) → 달라진다, 그래서 꺼낼 때 기록 · 큐(FIFO) → 같다, 그래서 자유롭다
정리

DFS와 BFS, 무엇을 언제 쓰는가

깊이 우선 탐색 (DFS)너비 우선 탐색 (BFS)
보조 자료구조스택 (재귀 = 호출 스택)큐 (deque)
꺼내는 위치pop() — 맨 뒤 (LIFO)popleft() — 맨 앞 (FIFO)
방문 순서a b d h e i j c f k ga b c d e f g h i j k
탐색 모양한 갈래로 깊게 내려갔다가 되돌아옴루트 주위로 레벨별로 퍼짐
최단 경로보장하지 않음보장 (간선 비용이 모두 같을 때)

이럴 때 쓴다
  • 모든 경우의 수를 빠짐없이 만들 때 (조합·순열·부분집합)
  • 경로가 있는지 없는지만 확인하면 될 때
  • 조건을 만족하는 답 하나만 찾으면 될 때
  • 사이클이 있는지 확인할 때
  • 최소 이동 횟수를 구할 때
  • 거리(레벨)별로 나눠서 처리해야 할 때
  • 출발점에서 가장 가까운 답을 찾을 때
  • “n초 후”처럼 한 겹씩 퍼지는 상황일 때

🧩 DFS가 맞는 문제 — 예시로 보기

문제왜 DFS인가
미로에 출구가 있는가? 있는지 여부만 알면 된다. 한 갈래를 끝까지 파보고, 막히면 되돌아와 다음 갈래. 찾는 즉시 종료할 수 있다.
1~9 중 3개를 골라 합이 15인 조합은? 모든 조합을 빠짐없이 만들어야 한다. 각 수마다 “고른다 / 안 고른다”를 정하며 끝까지 내려가는 것이 곧 DFS다.
스도쿠 · N-Queens 답을 만들어 가다 모순이 생기면 되돌아온다. 이 “되돌아옴”이 백트랙 그 자체다.
공통점: 한 번에 완성된 후보 하나를 손에 들고 있다. 스택에는 지금 내려온 경로만 들어 있으므로, 그 경로가 곧 “현재 만들고 있는 답”이 된다. 메모리도 적게 든다.

🎯 BFS가 맞는 문제 — 예시로 보기

문제왜 BFS인가
미로를 최소 몇 칸 움직여 탈출? 가까운 곳부터 한 겹씩 넓혀 가므로, 출구를 처음 만나는 순간이 곧 최솟값이다. 더 볼 필요가 없다.
나와 이 사람은 몇 다리 건너인가? 친구의 친구… 로 한 겹씩 넓히면 레벨이 곧 답이다. 깊이 파고들면 몇 다리인지 알 수 없다.
1초마다 한 칸씩 번지는 불 · 전염 “1초 = 한 레벨”이 정확히 맞아떨어진다. 같은 층을 다 처리한 뒤 다음 층으로 넘어가는 순서가 시간의 흐름과 같다.
공통점: 답이 “몇 번 만에”라는 숫자다. 큐에는 한 레벨 전체가 들어가므로 메모리는 더 쓰지만, 그 대가로 최소를 보장받는다.

🔍 문제에 이런 말이 나오면

문제 속 표현고른다
“최소 몇 번”, “최단 거리”, “가장 가까운”, “몇 단계 만에”BFS
“모든 경우”, “몇 가지 방법”, “가능한가?”DFS
“조합”, “순열”, “부분집합”, “골라서 만들기”DFS
“n초 후”, “동시에 퍼진다”, “레벨별로”BFS
“사이클이 있는가”, “되돌아오는 길이 있는가”DFS

※ 물론 절대 규칙은 아니다. 다만 “최소”라는 말이 보이면 일단 BFS를 의심하는 습관은 대체로 맞는다.

💬 판단 기준 한 줄
“몇 번 만에 갈 수 있나?” → BFS
“갈 수 있는 방법이 몇 가지인가? / 조건에 맞는 조합이 있나?” → DFS
⚠️ 자주 하는 착각
DFS로 먼저 찾은 경로를 최단이라고 믿는 것. DFS는 먼저 눈에 띈 경로일 뿐이다. 한 갈래를 끝까지 파고든 결과라서, 훨씬 짧은 길이 옆에 있어도 그냥 지나친다.

🤔 실제로는 DFS를 더 자주 쓴다

구현이 간단한 깊이 우선 탐색이 실제로 더 많이 쓰인다. 재귀 함수로 3~4줄이면 되고, 4차시의 백트래킹과 5차시의 분기 한정법이 모두 DFS 위에 세워지기 때문이다.

⚖️ 총 작업량은 같다

둘 다 모든 노드를 정확히 한 번씩 방문한다. 그래서 시간 복잡도가 똑같이 O(n)이다.
달라지는 것은 순서와 메모리, 그리고 답을 언제 만나는가뿐이다.

확인 활동

직접 예측해 보기

아래는 다른 트리다. 루트 1에서 출발하고, 자식은 번호가 작은 것부터 방문한다.

1의 자식: 2, 3  /  2의 자식: 4, 5  /  3의 자식: 6
4의 자식: 7, 8  /  6의 자식: 9

Q1. DFS(1)의 방문 순서는?
1→2→4→7 로 끝까지 내려간다. 7은 단말이므로 백트랙해서 8, 다시 백트랙해서 5, 또 백트랙해서 3 → 6 → 9. 깊게 파고들었다가 되돌아온다는 성질이 그대로 보인다.
Q2. BFS(1)의 방문 순서는?
레벨 0: {1} → 레벨 1: {2, 3} → 레벨 2: {4, 5, 6} → 레벨 3: {7, 8, 9}. 큐에 들어간 순서대로 나오므로 번호 순과 똑같아진다. 레벨을 하나씩 완전히 끝내고 다음으로 넘어간다.
Q3. 루트 1에서 노드 9까지의 최소 이동 횟수는?
1→3→6→9 로 간선 3개, 즉 노드 9의 레벨이 3이다. 트리에서는 두 노드를 잇는 경로가 하나뿐이므로 답도 하나다. BFS의 레벨 배열에서 level[9] = 3 으로 바로 읽어낼 수 있다.
Q4. 이 트리의 간선 수는?
노드가 n개인 트리의 간선은 항상 n − 1개다. 루트를 뺀 모든 노드가 부모와 이어지는 간선을 정확히 하나씩 갖기 때문이다. 노드 9개 → 간선 8개.
Wrap-up

오늘 배운 것, 한 장 정리

알고리즘푸는 문제보조 자료 구조 다음에 꺼낼 것시간 복잡도한 줄 요약
DFS
깊이 우선 탐색		 모든 노드 순회, 모든 경우의 수스택 / 재귀 가장 최근에 발견한 것O(n)끝까지 내려갔다가 되돌아온다(백트랙)
BFS
너비 우선 탐색		 최소 이동 횟수, 레벨별 처리큐 (deque) 가장 먼저 발견한 것O(n)가까운 레벨부터 한 겹씩

🔑 오늘의 핵심 하나

두 알고리즘의 뼈대는 완전히 같다.
“대기열에서 하나 꺼내 → 자식을 확인 → 다시 넣는다”
달라지는 것은 어느 쪽에서 꺼내는가뿐이다. 뒤에서 꺼내면 DFS, 앞에서 꺼내면 BFS다.

⚠️ 자주 하는 실수

  • 명시적 스택에서 reversed를 빠뜨림 → 순서가 거꾸로
  • DFS로 찾은 경로를 최단 경로로 착각
  • 큐를 list.pop(0)으로 구현 → O(n²)
  • 단말 노드를 딕셔너리에 빠뜨림 → KeyError
  • 재귀 깊이 제한을 잊음 (기본 1000)

스스로 확인하기

선택지를 눌러 답을 확인하세요.

1. 다음 중 비선형 구조를 탐색하는 알고리즘끼리 묶인 것은?
선형 구조(리스트·큐·스택)는 순차 탐색·이분 탐색으로, 비선형 구조(트리·그래프)는 깊이 우선 탐색·너비 우선 탐색으로 탐색한다.
2. DFS에서 더 갈 곳이 없어 부모 노드로 되돌아가는 과정을 무엇이라 하는가?
백트랙이다. 이 원리를 이용해 조건에 맞지 않는 가지를 잘라내며 탐색하는 기법이 백트래킹이며, 다음 차시의 주제다.
3. 트리에서 루트로부터 어떤 노드까지의 최소 이동 횟수를 구할 때 가장 적절한 것은?
BFS는 레벨이 얕은 순서로 탐색하므로 어떤 노드를 처음 만나는 순간이 곧 그 노드의 레벨이다. DFS는 먼저 찾은 경로가 최단이라는 보장이 없다.
4. 노드가 n개인 트리에 대한 설명으로 옳은 것은?
루트를 뺀 모든 노드가 부모와 이어지는 간선을 정확히 하나씩 가지므로 간선은 n − 1개다. 두 알고리즘 모두 모든 노드를 한 번씩만 방문하므로 시간 복잡도는 똑같이 O(n)이다. 달라지는 것은 순서와 메모리뿐이다.
5. 같은 트리에서 BFS가 DFS보다 메모리를 많이 쓰는 이유는?
DFS의 스택에는 루트에서 현재까지의 경로만 들어 있어 크기가 트리의 높이만큼이다. BFS의 큐에는 한 레벨 전체가 들어가므로, 넓은 트리일수록 급격히 커진다.
6. 트리 DFS 코드에는 visited 검사가 없어도 되지만, 그래프에서는 반드시 필요하다. 왜인가?
트리는 사이클이 없고 자식 쪽으로만 내려가므로 같은 노드를 두 번 만날 수 없다. 반면 그래프에서는 A → B → A → B … 로 영원히 돌 수 있어 방문 표시가 필수다. 이때 시간 복잡도 표기도 O(n)에서 O(V + E)로 바뀐다.
7. 완전 이진 트리의 모든 노드를 DFS로 순회할 때 시간 복잡도는?
이진 트리라도 순회는 모든 노드를 봐야 하므로 O(n)이다. O(log n)은 이진 탐색 트리에서 값을 찾을 때처럼 정렬 조건 덕에 절반을 버릴 수 있을 때 나온다. 갈라지는 것과 버리는 것은 다르다.
