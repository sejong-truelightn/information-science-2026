Motivation

전체 탐색은 옳다. 다만 끝나지 않을 뿐이다.2·3차시에서 우리는 상태 공간을 ‘전부’ 훑었다. 그 대가를 이제 계산해 본다.

전체 탐색기반 알고리즘은 해가 될 수 있는 모든 경우를 탐색한다. 컴퓨터의 계산 능력을 빌리면 빠르고 정확하게 해를 찾을 수 있다. 그러나 상태 공간의 크기가 매우 클 경우에는 해결이 어렵다.

특히 O(2ⁿ), O(3ⁿ) 같은 지수 형태의 시간 복잡도를 가지는 알고리즘은, 입력 n이 조금만 커져도 수행 시간이 기하급수적으로 늘어난다.

그래서 무엇을 해야 하는가?
컴퓨터를 더 빠르게 만드는 대신 탐색 전략을 최적화한다.
“더 이상 탐색을 진행하지 않아도 해를 구하는 데 문제가 없는 부분”을 판단해, 그 부분은 아예 보지 않는다.
Concept

상태 공간의 배제탐색 전략을 효율적으로 설계함으로써 상태 공간의 크기를 줄이는 알고리즘 설계 방법. 부분 탐색이라고도 한다.

백화점에 갔다. 사야 할 것은 양말 하나뿐이다.
“가구 구역에는 내가 사야 할 물건이 없으니, 이곳은 그냥 통과!”
— 가구 구역을 둘러본 뒤 없다고 판단한 것이 아니다. 들어가 보지도 않고 없다고 판단할 수 있었기 때문에 통과한 것이다.

❌ 무엇이 배제가 아닌가

  • 다 탐색한 뒤 답만 골라내는 것 — 시간은 그대로다.
  • “아마 없을 것 같으니” 하고 근거 없이 버리는 것 — 정답을 잃는다.
  • 코드를 짧게 쓰는 것 — 배제는 실행 횟수를 줄이는 일이다.

⭕ 배제의 조건

  • 탐색을 진행하기 전에 판단할 수 있어야 한다.
  • 판단의 논리적 근거가 분명해야 한다.
  • 버린 영역에 답이 없음이 보장되어야 한다. (분기 한정법)
  • 보장이 없다면 — 답이 아니라 ‘괜찮은 답’을 얻는다. (탐욕법)

🔑 오늘의 두 가지 방법

분기 한정법
DFS로 전체 탐색을 하다가, 이 아래에는 답이 없다고 판단되면 그 가지를 잘라내고 백트랙한다. 최적해를 보장한다.

탐욕법
다음 상태를 고를 때 지금 가장 좋아 보이는 하나만 남기고 나머지를 전부 버린다. 빠르지만 최적해를 보장하지 못한다.

🧠 한 문장으로

전체 탐색이 “모든 곳을 본다”였다면, 상태 공간의 배제는 “볼 필요가 없는 곳을 논리로 증명하고 지운다”이다.

📎 3차시와의 연결

3차시에서 배운 백트랙은 “더 갈 곳이 없어서 되돌아오는” 동작이었다.
오늘의 분기 한정은 갈 곳이 남아 있는데도 스스로 되돌아오는 백트랙이다. 같은 동작, 다른 이유.

Recap

우리는 이미 배제를 해 보았다4차시 교과서 문제 풀이 속에 오늘의 아이디어가 숨어 있었다. 이번 시간에는 그것에 이름을 붙이고 원리를 정리한다.

① 소수 판정 — √n까지만

약수는 짝으로 나온다. 짝의 작은 쪽은 언제나 √n 이하이므로, 그 위는 보지 않아도 결론이 같다.

선형 구조에서의 배제 — 탐색 범위를 줄인다.

② 계단 오르기 — 지나치면 버린다

c > n 이 된 순간, 그 아래 어떤 경로도 n번 칸에 정확히 도착할 수 없다. 그래서 더 내려가지 않는다.

비선형 구조에서의 배제 — 가지를 자른다.

③ BFS — 처음 찾은 답이 최소

레벨 순으로 훑으면 처음 도착한 답이 곧 최소 횟수다. 나머지 상태는 볼 필요가 없다.

탐색 순서를 바꿔 배제를 얻는다.

세 경우의 공통점 — 버린 영역에 답이 없다는 것을 탐색하기 전에, 논리로 알 수 있었다.
이 판단을 체계적으로 세우는 방법이 분기 한정법이고, 판단을 과감하게 세우는 방법이 탐욕법이다.
Branch and Bound

분기 한정법 탐색 과정에서 더 이상 탐색할 필요가 없다고 판단되는 경로에 대해 탐색을 진행하지 않고 백트랙을 수행하는 방식

탐색 진행

아직 없음
1 / 1
현재 노드 탐색 완료 배제된 영역
2번에서 3번으로 진행하려 할 때, “3번 아래에는 답이 없다”고 판단할 방법이 있다면?
3~8번을 통째로 건너뛰고 바로 9번으로 갈 수 있다. 탐색 11회 → 6회.

🔍 정의

탐색을 제한하는 규칙을 정확하게 수립하여 최적해를 구하는 알고리즘. 일반적으로 DFS 형태로 전체 탐색을 진행하다가, 탐색이 불필요한 노드가 발견되면 백트랙을 수행한다.

👍 장점

  • 해를 구할 때까지 모든 가능성을 탐색하지 않아도 된다.
  • 규칙이 옳다면 최적해를 그대로 보장한다. (버린 곳에 답이 없음이 증명되어 있으므로)

👎 단점 · 주의

  • 배제 규칙을 잘못 세우면 정답을 잃는다.
  • 최악의 경우 아무것도 잘리지 않아 전체 탐색과 같아질 수 있다. (시간 복잡도의 상한은 그대로)
노드가 뻗어 나가는 간선을 제거하는 방법이므로, 분기 한정 알고리즘 설계 방법은 일종의 가지치기(pruning)라고 할 수 있다.
Branch and Bound

무엇을 근거로 자르는가분기 한정법의 가지치기 규칙은 크게 두 종류다.

✂️ ① 조건 위반 — “이 길은 답이 될 수 없다”

지금 상태가 이미 문제의 조건을 어겼다면, 아래로 무엇을 더 붙여도 조건을 회복할 수 없다.

  • 합이 목표를 넘었다 (더하는 수가 모두 양수)
  • 무게가 가방 용량을 넘었다
  • 퀸끼리 서로 공격한다

해의 존재 여부를 묻는 문제에서도 쓸 수 있다. 백트래킹이라고도 부른다.

📏 ② 한계(bound) — “이 길은 더 좋아질 수 없다”

조건은 지키고 있지만, 이 아래에서 얻을 수 있는 가장 좋은 값(상한)조차 지금까지 찾은 최선을 넘지 못한다면 볼 필요가 없다.

지금 값 + 남은 것으로 얻을 수 있는 최대 ≤ 최선 → 자른다

최적화 문제(최대·최소)에서 쓴다. 분기 한정(bound)이라는 이름이 여기서 나왔다.

🔁 최선값은 계속 바뀐다

더 좋은 해를 찾을 때마다 최선값이 갱신되고, 그만큼 잘리는 가지가 늘어난다.

🧭 탐색 순서가 성능을 정한다

좋은 해를 일찍 찾을수록 한계가 빨리 높아져 더 많이 자른다. 그래서 유망해 보이는 쪽부터 탐색한다.

⚖️ 상한은 낙관적이어야 한다

상한은 실제 최댓값보다 작으면 안 된다. 작게 어림하면 답이 있는 가지까지 잘라 정답을 잃는다.

Example — 0/1 배낭 문제

가방에 담을 수 있는 가장 큰 가치는?용량 9kg인 가방에 물건 A~D를 넣거나 넣지 않거나 정한다. 각 물건은 한 번만 넣을 수 있다.

현재 노드 방문 최선 갱신 잘려서 보지 않음 왼쪽 간선 = 넣는다 · 오른쪽 = 넣지 않는다 · 노드 숫자 = 지금까지의 가치
물건ABCD
무게6541
가치12981

지금 상태

아직 없음
최선 0   방문 0 / 31
1 / 1

🔍 무엇을 확인했나

  • 전체 탐색이라면 노드 31개를 모두 본다.
  • 분기 한정법은 15개만 보고 같은 답 17(B + C)을 찾는다.
  • 무게 초과로 3번, 한계로 2번 잘랐다.
‘--’ 노드가 잘린 이유
A, B를 모두 빼면 남은 C, D를 다 넣어도 8 + 1 = 9. 이미 17을 찾았으므로 볼 필요가 없다. 
W = 9
w = [6, 5, 4, 1]       # 무게
v = [12, 9, 8, 1]      # 가치
best = 0

def f(i, cw, cv):           # i번째 물건을 정할 차례
    global best
    if cw > W:                 # ① 조건 위반 — 무게 초과
        return
    if i == len(w):            # 모든 물건을 정했다
        best = max(best, cv)
        return
    if cv + sum(v[i:]) <= best: # ② 한계 — 다 넣어도 최선 이하
        return
    f(i+1, cw+w[i], cv+v[i])  # 넣는다
    f(i+1, cw, cv)            # 넣지 않는다

f(0, 0, 0)
print(best)                   # 17
Greedy

탐욕법 현재 상태에서 다음 상태를 탐색할 때, 모든 가능한 상태를 고려하지 않고 최선의 상태만을 선택한다.

🔍 정의

주어진 문제에서 전체 상태 공간 중 일부를 배제하여 문제를 해결하는 알고리즘.

여러 개의 해가 존재하는 최적화 문제에서 탐욕적 선택을 통하여 가장 적절한 해를 찾는다.

욕심쟁이 알고리즘 · 그리디 알고리즘(greedy algorithm)이라고도 부른다.

✂️ 무엇을 배제하는가

갈림길에서 선택지가 b개일 때,
분기 한정법은 “답이 없음이 증명된” 가지만 자른다.

탐욕법은 가장 좋아 보이는 하나만 남기고 나머지 b−1개를 전부 자른다.

그래서 탐색 경로는 단 하나의 줄기가 되고, 백트랙이 일어나지 않는다.

⚡ 그 대가로 얻는 것

깊이가 n인 이진 트리에서
전체 탐색: O(2ⁿ)
탐욕법: O(n)

대신 그 답이 최적해라는 보장은 사라진다.

🧩 탐욕법을 설계하는 순서

  1. 선택 기준을 정한다. — “무엇이 지금 가장 좋은가?”
  2. 기준에 따라 하나를 고르고, 조건을 어기면 버린다.
  3. 남은 부분 문제에 같은 기준을 반복한다.
  4. 이 기준이 최적해를 주는지 확인한다. — 가장 중요하고, 가장 자주 빠뜨리는 단계
앞의 배낭 문제에 탐욕법을 쓰면?
기준: “가치가 큰 물건부터 넣는다”
A(12) 넣음 → 남은 용량 3 → B, C는 못 넣음 → D(1) 넣음 → 13

비교는 4번이면 끝나지만, 최적해 17보다 나쁘다.
“무게당 가치가 큰 것부터”로 바꿔도 A가 먼저 들어가 13이다.
Example — 회의실 배정

기준만 잘 고르면 탐욕법이 정답이다회의실 하나에 회의 8개가 신청되었다. 시간이 겹치지 않게 가장 많은 회의를 배정해 보자. (끝나는 시각에 다음 회의가 바로 시작할 수 있다)

선택 기준

배정된 회의

아직 없음
1 / 1
지금 보는 회의 배정 겹쳐서 버림

✅ 왜 ‘끝나는 시각’인가

최적의 배정 하나를 생각하자. 그 첫 회의를 가장 먼저 끝나는 회의로 바꿔도 뒤의 회의와 겹치지 않는다(더 일찍 끝나므로). 개수는 그대로다.

즉, 탐욕적 선택을 해도 최적해를 잃지 않는다. 남은 시간에 같은 논리를 반복하면 끝까지 최적이다.

시작이 빠른 순으로 고르면 긴 회의 A가 0~6시를 다 차지한다. 짧은 순으로 고르면 C가 먼저 들어가서 B와 D를 둘 다 못 쓴다. 두 방법 모두 2개밖에 배정하지 못한다. 
meetings = [(0,6), (1,4), (3,5), (4,7),
            (5,9), (6,10), (8,11), (9,12)]

# 탐욕적 선택 기준 — 끝나는 시각이 빠른 것부터
def end_time(m):
    return m[1]                # m = (시작, 끝) → 끝나는 시각

meetings.sort(key=end_time)

cnt = 0
end = 0                       # 마지막으로 배정한 회의가 끝나는 시각
for s, e in meetings:
    if s >= end:               # 겹치지 않으면 배정
        cnt = cnt + 1
        end = e

print(cnt)                    # 3
Limitation

탐욕법의 논리적 비약“지금 가장 좋아 보이는 것을 고르면 전체도 가장 좋아진다” — 이 문장에는 논리적 근거가 없다.

현재 상태에서 가장 좋아 보이는 다음 상태를 고르는 것이, 전체 공간에서의 최적해를 보장한다는 논리적 근거는 없다. 배낭 문제가 그 예다.
따라서 최적의 결과를 얻기 위해서는 더욱 체계적이고 논리적인 방식의 알고리즘 개발이 필요하다.

① 탐욕적 선택 속성

지금 탐욕적으로 고른 것을 포함하는 최적해가 반드시 존재한다. 회의실 배정의 ‘가장 먼저 끝나는 회의’가 그렇다.

② 최적 부분 구조

하나를 고르고 남은 부분 문제의 최적해를 붙이면 전체의 최적해가 된다.

두 성질을 모두 보일 수 있을 때 탐욕법은 정답을 준다. 하나라도 무너지면 ‘괜찮은 답’일 뿐이다.

✅ 탐욕법이 최적해를 주는 경우

탐욕적 선택이 최적해로 이어진다는 것을 증명할 수 있을 때만 탐욕법은 정당하다.

1. 다익스트라 알고리즘

단일 출발점에서 다른 모든 정점으로의 최단 경로를 찾는 알고리즘.

2. 허프만 알고리즘

데이터 압축에 사용된다. 가장 낮은 빈도로 나타나는 문자부터 차례대로 두 개씩 묶어 나가며 새로운 이진 트리를 구성한다.

3. 최소 신장 트리 (크루스칼 · 프림)

싼 간선부터 고르는 탐욕적 선택이 최소 비용을 보장한다.

기억할 것
탐욕법을 이용하여 최적해를 구하기 위해서는, 탐색할 다음 상태를 선택할 때 논리적 근거가 필요하다.

Check

스스로 확인하기선택지를 눌러 정답과 해설을 확인해 보자.

Q1. 분기 한정법과 탐욕법의 가장 큰 차이는?
분기 한정법은 답이 없음이 증명된 가지만 자르므로 최적해가 그대로 남는다. 탐욕법은 증명 없이 나머지를 전부 버리므로, 버린 쪽에 더 좋은 답이 있을 수 있다. 둘 다 상태 공간을 배제한다는 점은 같다.
Q2. 배낭 문제 코드에서 ② 한계 조건 if cv + sum(v[i:]) <= best 를 지우면?
배제는 답을 바꾸지 않고 시간을 바꾼다. 무게 초과는 ① 조건이 따로 막고 있으므로 답은 17 그대로다. 다만 한계로 잘라 내던 가지까지 모두 내려가 보게 된다.
Q3. 한계(상한)를 실제로 얻을 수 있는 값보다 작게 어림하면?
한계는 “이 아래에서 아무리 잘해도 이 값을 넘지 못한다”는 약속이다. 실제보다 작게 잡으면 그 약속이 거짓이 되어, 최적해가 있는 가지를 버릴 수 있다. 상한은 낙관적으로 잡아야 한다.
Q4. 회의 (0~5), (4~7), (6~11) 이 있다. ‘짧은 회의부터’ 고르면 몇 개를 배정하는가?
가장 짧은 (4~7)을 먼저 고르면 나머지 둘과 모두 겹쳐 1개로 끝난다. 끝나는 시각 기준이라면 (0~5) → (6~11) 로 2개. 그럴듯한 기준이라도 근거가 없으면 최적해를 놓친다.
Q5. 분기 한정법에서 좋은 해를 일찍 찾으면 어떻게 되는가?
한계 가지치기는 지금까지의 최선과 비교한다. 최선이 높을수록 “더 좋아질 수 없는” 가지가 많아진다. 다만 남은 가지에 더 좋은 해가 있을 수 있으므로 바로 끝내서는 안 된다. 그래서 유망한 쪽부터 탐색한다.
Q6. 다음 중 상태 공간의 배제라고 할 수 없는 것은?
③은 탐색을 다 한 뒤에 걸러내는 것이므로 수행 시간이 전혀 줄지 않는다. 배제는 탐색을 시작하기 전에 판단해서 실행 자체를 하지 않는 것이다.
