Motivation

전체 탐색은 옳다. 다만 끝나지 않을 뿐이다.2·3차시에서 우리는 상태 공간을 ‘전부’ 훑었다. 그 대가를 이제 계산해 본다.

전체 탐색기반 알고리즘은 해가 될 수 있는 모든 경우를 탐색한다. 컴퓨터의 계산 능력을 빌리면 빠르고 정확하게 해를 찾을 수 있다. 그러나 상태 공간의 크기가 매우 클 경우에는 해결이 어렵다.

특히 O(2ⁿ), O(3ⁿ) 같은 지수 형태의 시간 복잡도를 가지는 알고리즘은, 입력 n이 조금만 커져도 수행 시간이 기하급수적으로 늘어난다.

n이 10 커질 때마다 시간은 약 1,000배가 된다. ‘컴퓨터가 더 빨라지면 되지 않나?’라는 기대가 통하지 않는 영역이다.

참고: 관측 가능한 우주의 원자 수는 약 1080개다. 바둑판 하나의 상태 공간이 우주보다 크다.

그래서 무엇을 해야 하는가?
컴퓨터를 더 빠르게 만드는 대신 탐색 전략을 최적화한다.
“더 이상 탐색을 진행하지 않아도 해를 구하는 데 문제가 없는 부분”을 판단해, 그 부분은 아예 보지 않는다.
Concept

상태 공간의 배제탐색 전략을 효율적으로 설계함으로써 상태 공간의 크기를 줄이는 알고리즘 설계 방법. 부분 탐색이라고도 한다.

백화점에 갔다. 사야 할 것은 양말 하나뿐이다.
“가구 구역에는 내가 사야 할 물건이 없으니, 이곳은 그냥 통과!”
— 가구 구역을 둘러본 뒤 없다고 판단한 것이 아니다. 들어가 보지도 않고 없다고 판단할 수 있었기 때문에 통과한 것이다.

❌ 무엇이 배제가 아닌가

  • 다 탐색한 뒤 답만 골라내는 것 — 시간은 그대로다.
  • “아마 없을 것 같으니” 하고 근거 없이 버리는 것 — 정답을 잃는다.
  • 코드를 짧게 쓰는 것 — 배제는 실행 횟수를 줄이는 일이다.

⭕ 배제의 조건

  • 탐색을 진행하기 전에 판단할 수 있어야 한다.
  • 판단의 논리적 근거가 분명해야 한다.
  • 버린 영역에 답이 없음이 보장되어야 한다. (분기 한정법)
  • 보장이 없다면 — 답이 아니라 ‘괜찮은 답’을 얻는다. (탐욕법)

🔑 오늘의 두 가지 방법

분기 한정법
DFS로 전체 탐색을 하다가, 이 아래에는 답이 없다고 판단되면 그 가지를 잘라내고 백트랙한다. 최적해를 보장한다.

탐욕법
다음 상태를 고를 때 지금 가장 좋아 보이는 하나만 남기고 나머지를 전부 버린다. 빠르지만 최적해를 보장하지 못한다.

🧠 한 문장으로

전체 탐색이 “모든 곳을 본다”였다면, 상태 공간의 배제는 “볼 필요가 없는 곳을 논리로 증명하고 지운다”이다.

📎 3차시와의 연결

3차시에서 배운 백트랙은 “더 갈 곳이 없어서 되돌아오는” 동작이었다.
오늘의 분기 한정은 갈 곳이 남아 있는데도 스스로 되돌아오는 백트랙이다. 같은 동작, 다른 이유.

Example 0

배제의 첫 경험 — 어디까지 나눠 보면 되는가100 이하의 자연수 n이 주어질 때, 1부터 n까지 자연수에 포함된 소수의 개수를 출력해 보자.

🔑 배제의 근거

k = a × b 이면, a와 b 둘 중 하나는 항상 √k 보다 작거나 같다.

둘 다 √k보다 크다면 a×b > √k×√k = k 가 되어 모순이기 때문이다.
→ 2부터 √k까지만 확인해서 나누어지지 않으면, k는 소수임이 확정된다.

k \ i23456789소수 여부

3확인할 i가 없음소수
4O배제합성수
5X배제소수

k=2~10에서 2부터 k−1까지 확인하면 36회, 2부터 √k까지만 확인하면 9회. 시간 복잡도는 O(n²) → O(n√n).

for i in range(2, n+1):
  cnt = 0
  for j in range(2, int(i**(1/2))+1):   # ← 여기서 배제가 일어난다

알고리즘의 구조는 그대로인데 상태 공간의 크기가 달라졌다. 이것이 배제의 전형적인 모습이다.
Branch and Bound

분기 한정법 탐색 과정에서 더 이상 탐색할 필요가 없다고 판단되는 경로에 대해 탐색을 진행하지 않고 백트랙을 수행하는 방식

탐색 진행

아직 없음
1 / 1
현재 노드 탐색 완료 배제된 영역
2번에서 3번으로 진행하려 할 때, “3번 아래에는 답이 없다”고 판단할 방법이 있다면?
3~8번을 통째로 건너뛰고 바로 9번으로 갈 수 있다. 탐색 11회 → 6회.

🔍 정의

탐색을 제한하는 규칙을 정확하게 수립하여 최적해를 구하는 알고리즘. 일반적으로 DFS 형태로 전체 탐색을 진행하다가, 탐색이 불필요한 노드가 발견되면 백트랙을 수행한다.

👍 장점

  • 해를 구할 때까지 모든 가능성을 탐색하지 않아도 된다.
  • 규칙이 옳다면 최적해를 그대로 보장한다. (버린 곳에 답이 없음이 증명되어 있으므로)

👎 단점 · 주의

  • 배제 규칙을 잘못 세우면 정답을 잃는다.
  • 최악의 경우 아무것도 잘리지 않아 전체 탐색과 같아질 수 있다. (시간 복잡도의 상한은 그대로)
노드가 뻗어 나가는 간선을 제거하는 방법이므로, 분기 한정 알고리즘 설계 방법은 일종의 가지치기(pruning)라고 할 수 있다.

Code

코드에서 배제는 어디에 있는가재귀 함수 f(s, k) — s는 지금까지의 합, k는 앞으로 더 더해야 할 수의 개수

ans = 0

def f(s, k):
  if k==0:
    if n==s:
      return 1
    else:
      return 0
  if s>n:            # 더 이상 탐색하지 않고 백트랙
    return 0

  cnt = 0
  for i in range(1, n+1):
    cnt = cnt+f(s+i, k-1)
  return cnt

n = int(input())
for i in range(1, n+1):
    ans = ans+f(0, i)

print(ans)

🔍 정의

주어진 문제에서 전체 상태 공간 중 일부를 배제하여 문제를 해결하는 알고리즘.

여러 개의 해가 존재하는 최적화 문제에서 탐욕적 선택을 통하여 가장 적절한 해를 찾는다.

욕심쟁이 알고리즘 · 그리디 알고리즘(greedy algorithm)이라고도 부른다.

✂️ 무엇을 배제하는가

갈림길에서 선택지가 b개일 때,
분기 한정법은 “답이 없음이 증명된” 가지만 자른다.

탐욕법은 가장 좋아 보이는 하나만 남기고 나머지 b−1개를 전부 자른다. 증명 없이.

그래서 탐색 경로는 단 하나의 줄기가 되고, 백트랙이 아예 일어나지 않는다.

⚡ 그 대가로 얻는 것

깊이가 n인 이진 트리에서
전체 탐색: O(2ⁿ)
탐욕법: O(n)

n=50이면 3.6년 → 눈 깜짝할 사이.
대신 그 답이 최적해라는 보장은 사라진다.

오늘의 문제: 루트 노드부터 단말 노드로 이동할 때, 이동 경로에 있는 노드 합의 최댓값을 구해 보자.
전체 탐색으로 푼다면 모든 경로의 합을 계산해야 하고, 트리의 높이가 n일 때 시간 복잡도는 O(2ⁿ)이다.

전체 탐색이라면 계산해야 하는 것 (8갈래)

9+9+1+8   9+9+1+6   9+9+2+2   9+9+2+1
9+8+9+9   9+8+9+5   9+8+9+8   9+8+9+6

탐욕법이라면 계산해야 하는 것 (3번의 비교)

9 vs 8  →  9
1 vs 2  →  2
2 vs 1  →  2

Limitation

탐욕법의 논리적 비약“지금 가장 큰 것을 고르면 전체 합도 가장 커진다” — 이 문장에는 논리적 근거가 없다.

현재 상태에서 다음 상태로 이동할 때 가장 큰 값을 가진 노드를 선택하는 것이, 전체 공간에서의 최대 합을 보장한다는 논리적 근거는 없다.
따라서 최적의 결과를 얻기 위해서는 더욱 체계적이고 논리적인 방식의 알고리즘 개발이 필요하다.

✅ 탐욕법이 최적해를 주는 경우

탐욕적 선택이 최적해로 이어진다는 것을 증명할 수 있을 때만 탐욕법은 정당하다.

1. 다익스트라 알고리즘

단일 출발점에서 다른 모든 정점으로의 최단 경로를 찾는 알고리즘.

2. 허프만 알고리즘

데이터 압축에 사용된다. 가장 낮은 빈도로 나타나는 문자부터 차례대로 두 개씩 묶어 나가며 새로운 이진 트리를 구성한다.

3. 최소 신장 트리 (크루스칼 · 프림)

싼 간선부터 고르는 탐욕적 선택이 최소 비용을 보장한다.

기억할 것
탐욕법을 이용하여 최적해를 구하기 위해서는, 탐색할 다음 상태를 선택할 때 논리적 근거가 필요하다.

막대 길이는 함수 호출(연산) 횟수를 로그 눈금으로 나타낸 것이다.

① 전체 탐색

동전 하나를 고르고, 또 하나를 고르는 과정을 반복한다. n원이 되면 개수를 비교하고, n원을 초과하면 백트랙한다.

ans = 987654321
coin = [500, 100, 50, 10]
def f(won, d):
  global ans
  if won>n:
    return
  if won==n:
    ans = min(d, ans)
    return
  for i in range(4):
    f(won+coin[i], d+1)
  return
n = int(input())
f(0, 0)
print(ans)
같은 금액을 순서만 바꿔 만드는 경우를 전부 세므로 폭발한다. 시간 복잡도 O(2ⁿ).

② 분기 한정법

이미 k개로 n원을 만든 적이 있다면, k개 이상을 쓰는 경로는 볼 필요가 없다.

ans = 987654321
coin = [500, 100, 50, 10]
def f(won, d):
  global ans
  if won>n:
    return
  if d>=ans:      # 분기 한정
    return
  if won==n:
    ans = min(d, ans)
    return
  for i in range(4):
    f(won+coin[i], d+1)
  return
n = int(input())
f(0, 0)
print(ans)
지금까지 찾은 최선의 답이 곧 한계선(bound)이 된다. 좋은 답을 빨리 찾을수록 더 많이 잘린다.

③ 탐욕법

가장 가치가 높은 동전부터 내림차순으로, n원을 초과하지 않도록 최대한 많이 내준다.

ans = 0
coin = [500, 100, 50, 10]

n = int(input())
for i in range(4):
    ans = ans+(n//coin[i])
    n = n%coin[i]

print(ans)
재귀도, 백트랙도 없다. 반복문 4번이면 끝난다.
시간 복잡도 O(2ⁿ) → O(m) (m은 동전의 가짓수)
🤔 그런데 이 탐욕법은 왜 정답인가?
10·50·100·500은 큰 단위가 작은 단위의 배수라서 큰 동전을 미루는 것이 결코 이득이 아님을 증명할 수 있다.
만약 동전이 [1, 4, 5]이고 8원을 낸다면? 탐욕법은 5+1+1+1 = 4개, 최적은 4+4 = 2개. 탐욕법이 틀린다.
Application 2

약수의 합 — 절반은 공짜로 얻는다100억 이하의 자연수 n이 주어질 때, n의 모든 약수의 합을 구해 보자.

① 전체 탐색

1부터 n까지 모든 수가 n의 약수인지 확인한다. 탐색해야 하는 상태는 1부터 n까지의 자연수.

ans = 0
n = int(input())

for i in range(1, n+1):
  if n%i==0:
    ans = ans+i

print(ans)
n에 100억이 입력되면 1부터 100억까지 연산해야 한다. 1초에 1,000만 번 연산하는 컴퓨터로 약 30분 이상.
시간 복잡도 O(n)

🔑 배제의 근거

n = a × b 일 때, a를 찾으면 b도 같이 찾은 것이다.

10 = 1×10    10 = 2×5
√10 ≈ 3.16  |  1, 2까지만 찾으면 10, 5는 계산 없이 따라온다

② 상태 공간 배제

1부터 √n 까지만 탐색하여 모든 약수의 합을 구한다. 단, √n이 자연수일 때 두 번 더해지는 것을 조심해야 한다.

ans = 0
n = int(input())

for i in range(1, int(n**(1/2))+1):
  if n%i==0:
    ans = ans+i
    ans = ans+(n//i)

if n==(int(n**(1/2))**2):   # n이 제곱수라면
  ans = ans-int(n**(1/2))    # √n이 두 번 더해졌다

print(ans)
n에 100억이 입력되면 1부터 100,000까지만 연산하면 된다. 1초 안에 해를 구할 수 있다.
시간 복잡도 O(√n)

스스로 확인하기선택지를 눌러 정답과 해설을 확인해 보자.

Q1. 분기 한정법과 탐욕법의 가장 큰 차이는?
분기 한정법은 답이 없음이 증명된 가지만 자르므로 최적해가 그대로 남는다. 탐욕법은 증명 없이 나머지를 전부 버리므로, 버린 쪽에 더 좋은 답이 있을 수 있다. 둘 다 상태 공간을 배제한다는 점은 같다.
Q2. f(s,k)에서 if s>n: return 0 을 삭제하면?
배제는 답을 바꾸지 않고 시간을 바꾼다. k가 0이 되면 재귀가 멈추므로 무한 재귀도 아니고, 합이 n이 아닌 경우는 어차피 0을 반환하므로 답도 그대로다. 다만 11,111,111,110가지를 전부 세게 된다.
Q3. 100 이하 소수를 셀 때 range(2, int(i**0.5)+1) 이 옳은 이유는?
√i보다 큰 약수는 존재한다(예: 10의 약수 5). 다만 그 짝이 되는 약수는 반드시 √i 이하에 있으므로, √i까지 하나도 나누어지지 않으면 그 위에도 없다고 확정할 수 있다.
Q4. 동전이 [1, 4, 5]원일 때 8원을 만드는 최소 개수를 탐욕법으로 구하면?
탐욕법: 5 → 남은 3 → 1+1+1 = 총 4개. 최적해: 4+4 = 2개.
큰 단위가 작은 단위의 배수가 아니면 탐욕적 선택의 정당성이 무너진다. 우리나라 동전 체계에서 탐욕법이 통하는 것은 우연이 아니라 설계다.
Q5. 최소 동전 문제에서 if d>=ans: return 이 잘라내는 것은?
금액 초과는 바로 윗줄 if won>n이 담당한다. d>=ans는 지금까지의 최선(ans)을 한계선으로 삼아, 그보다 나아질 가능성이 없는 경로를 잘라낸다. 좋은 답을 일찍 찾을수록 더 많이 잘린다는 것이 분기 한정법의 특징이다.
Q6. 다음 중 상태 공간의 배제라고 할 수 없는 것은?
③은 탐색을 다 한 뒤에 걸러내는 것이므로 수행 시간이 전혀 줄지 않는다. 배제는 탐색을 시작하기 전에 판단해서 실행 자체를 하지 않는 것이다.

2. 일반화된 규칙

위치를 정렬해 a < b < c 라 할 때,

최대 이동 횟수 = max(b−a, c−b) − 1

큰 쪽 간격 안의 빈 연잎 개수가 곧 이동 횟수다. 매번 한 칸씩만 좁히는 것이 탐욕적 선택이며, 이 경우에는 그 선택이 최적임을 증명할 수 있다.

3. 프로그램을 완성해 보자

data = list(map(int,input().split()))

data.sort()

if data[1]-data[0] > data[2]-data[1]:
  　 ①　

else:
  　 ②　

입력

1 8 10

실행 결과

6
① print(data[1]-data[0]-1)
② print(data[2]-data[1]-1)

3행의 data.sort()가 왜 필요할까? 입력이 8 1 10처럼 들어와도 ‘바깥—가운데—바깥’ 관계를 위치 순서로 판단해야 하기 때문이다.

📌 정리하기

  • 탐색기반 알고리즘은 가능한 해의 집합을 체계적으로 탐색하여 문제의 최적해를 찾는 방법이다.
  • 선형 구조는 상태 공간을 탐색하는 순서를 유일하게 결정할 수 있다. 2차시
  • 비선형 구조는 특정 원소를 탐색한 후, 그 원소와 연결된 여러 개의 다른 원소 중 다음에 탐색할 원소를 선택하는 탐색 구조를 뜻한다. 3차시
  • 상태 공간의 배제는 탐색 전략을 효율적으로 설계하여 상태 공간을 축소하는 알고리즘 설계 방법이며, 이를 통하여 부분 탐색이 가능해진다.
  • 분기 한정법은 상태 공간을 배제하여 탐색기반 알고리즘의 효율을 향상시키는 방법 중 하나이다.
  • 탐욕법은 현재 상태에서 최선의 상태만을 선택하여 다음 상태로 이동하는 방식을 사용한다.
